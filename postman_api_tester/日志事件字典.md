# 日志事件字典（v1.35.0）

发布日期：2026-08-25
文档定位：统一列出结构化日志 `event` 命名及触发时机，便于 ELK/检索系统聚合。
统计：共 169 个结构化事件（`extra={"event": ...}`），分布在 15 个域。

## 1. 命名规则

1. 统一格式：`domain.action.state`
2. 小写英文，使用 `.` 分段，不使用空格和下划线（`extra.event` 字段强制遵循）。
3. `domain` 取值：
   - 通用：`job`、`manual_case`、`report`、`handler`、`http`、`logging`、`test`、`service`、`checkpoint`、`log`
   - UI 模块：`ui.case`、`ui.recording`、`ui.execution`、`ui.report`、`ui.settings`、`ui.auth`、`ui.login_config`、`ui.proxy`（含子域 `ui.proxy.session` / `ui.proxy.page` / `ui.proxy.resource`）
   - 无头引擎：`headless`

> 注：`logger.info/warning/error` 的第一个 message 参数（如 `"headless_log_cleanup"`、`"ui_settings_reset"`、`"pre-request syntax error"`）属于自由文本日志消息，不属于结构化事件，不列入本字典。

## 2. 事件清单

### 2.1 执行链路（job/test）

- `job.run.started`：任务开始执行。
- `job.run.progress`：任务执行进度更新（采样输出）。
- `job.run.completed`：任务执行完成并已刷新报告索引。
- `job.run.failed`：任务执行失败。
- `job.enqueue.queued`：任务入队成功。
- `job.retry.queued`：重试任务入队。
- `job.retry.invalid_mode`：重试模式非法。
- `job.retry.context_failed`：重试上下文构建失败。
- `job.retry.context_ready`：重试上下文构建完成。
- `job.submit.params_built`：普通任务参数构建完成。
- `job.submit.adhoc_params_built`：ad-hoc 任务参数构建完成。
- `job.submit.path_built`：任务保存路径生成完成。
- `test.run.executed`：单接口执行结果记录。

### 2.2 人工用例链路（manual_case）

- `manual_case.add.created`：人工用例新增成功。
- `manual_case.update.updated`：人工用例更新成功。
- `manual_case.delete.deleted`：人工用例删除成功。
- `manual_case.exclusion.updated`：人工用例排除状态更新。

### 2.3 报告链路（report）

- `report.export.started`：报告导出开始。
- `report.export.completed`：报告导出完成。
- `report.delete.started`：报告删除开始。
- `report.delete.completed`：报告删除完成。

### 2.4 路由编排链路（handler）

- `handler.collection.preview.extracted`
- `handler.collection.adhoc_case.normalized`
- `handler.collection.adhoc_collection.built`
- `handler.collection.selected_paths.parsed`
- `handler.http.execute.received`
- `handler.http.execute.invalid_url`
- `handler.http.execute.invalid_body`
- `handler.http.execute.completed`
- `handler.http.execute.failed`
- `handler.server.report_delete.forward`（原 `handler.admin.report_delete.forward`，v1.33.0 重命名）
- `handler.error`：路由层统一错误（`@handle_api_errors` 装饰器捕获）。

> 注：v1.33.1 之前存在 `handler.job.*.forward` 和 `handler.manual_case.*.forward` 共 8 个事件，引入 `@handle_api_errors` 装饰器后统一合并到 `handler.error`，原事件已移除。

### 2.5 平台与访问日志（logging/http）

- `logging.configure.applied`：日志系统初始化完成。
- `http.access.logged`：服务端访问日志（请求级）。

### 2.6 UI 用例管理（ui.case）

- `ui.case.created`：UI 用例新增成功。
- `ui.case.updated`：UI 用例更新成功。
- `ui.case.deleted`：UI 用例删除成功。
- `ui.case.update_not_found`：更新时未找到目标用例。
- `ui.case.delete_not_found`：删除时未找到目标用例。

### 2.7 UI 录制（ui.recording）

- `ui.recording.started`：录制开始。
- `ui.recording.stopped`：录制结束。
- `ui.recording.session.new`：创建新录制会话。
- `ui.recording.session_cleared`：录制会话清空。
- `ui.recording.saved_as_case`：录制数据另存为 UI 用例。
- `ui.recording.cookies_exported`：录制停止时导出 Cookie 用于认证档案。

### 2.8 UI 执行与报告（ui.execution / ui.report）

- `ui.execution.created`：UI 执行任务创建。
- `ui.execution.completed`：UI 执行完成。
- `ui.execution.cancelled`：UI 执行被取消。
- `ui.execution.deleted`：UI 执行记录被删除。
- `ui.execution.cleanup`：UI 执行产物定期清理。
- `ui.execution.stale_cleanup`：僵尸 UI 执行清理（>30 分钟未完成）。
- `ui.execution.concurrent_limit`：触发并发上限拒绝新任务。
- `ui.execution.step_complete`：UI 执行单步完成（进度上报）。
- `ui.execution.screenshot_saved`：UI 执行失败步骤截图已保存。
- `ui.execution.init.cookies_cleared`：UI 执行初始化时已清空旧 Cookie。
- `ui.execution.auth_profile_loaded`：认证档案加载成功，将用于无头执行。
- `ui.execution.auth_profile_expired`：认证档案已过期，降级为无登录执行。
- `ui.execution.auth_profile_not_found`：认证档案不存在，降级为无登录执行。
- `ui.execution.auth_temp_write_failed`：认证状态临时文件写入失败，降级为无登录执行。
- `ui.execution.auth_temp_cleanup_failed`：认证状态临时文件清理失败。
- `ui.execution.thread_start_failed`：执行线程启动失败，清理临时文件并标记任务失败。
- `ui.execution.auth_refreshed`：认证档案通过登录配置自动刷新 Cookie。
- `ui.execution.login_config_not_found`：认证档案关联的登录配置不存在，降级为无登录执行。
- `ui.execution.login_config_empty`：登录配置步骤为空或 base_url 未配置。
- `ui.execution.login_config_error`：登录配置执行异常。
- `ui.execution.login_config_failed`：登录配置执行失败（步骤失败或 Cookie 为空）。
- `ui.report.deleted`：UI 执行报告删除。

### 2.9 UI 设置与 Webhook（ui.settings）

- `ui.settings.updated`：UI 测试设置更新。
- `ui.settings.reset`：UI 测试设置重置为默认。
- `ui.settings.webhook_sent`：Webhook 通知发送成功。
- `ui.settings.webhook_failed`：Webhook 通知发送失败。

- `ui.proxy.session.reuse`：复用已有会话。
- `ui.proxy.session.reuse_cross_origin`：跨域来源复用已有会话。
- `ui.proxy.session.reuse_referer`：通过 Referer 复用已有会话。
- `ui.proxy.session.origin_mismatch`：Origin 与会话不匹配。
- `ui.proxy.session.creating_new`：正在创建新会话。
- `ui.proxy.session.clear_summary`：会话清空摘要日志。
- `ui.proxy.session.cookies_cleared`：会话 Cookie 已被清空。
- `ui.proxy.session.jar_none`：会话无可用 Cookie Jar。
- `ui.proxy.session.browser_cookie_loaded`：从浏览器加载 Cookie 成功。
- `ui.proxy.session.browser_cookie_failed`：从浏览器加载 Cookie 失败。
- `ui.proxy.session.token_inherited`：会话继承父会话 Token。
- `ui.proxy.session.token_stored`：会话 Token 已持久化。
- `ui.proxy.session.subsystem_token_stored`：子系统 Token 已持久化。
- `ui.proxy.session.shared_token`：使用共享 Token。

- `ui.proxy.session.sessions_restored`：启动时恢复录制会话摘要日志。

- `ui.proxy.session.load_failed`：恢复录制会话文件失败（JSON 损坏等）。

## 3. 检索建议

1. 通用聚合维度：`event`、`status_code`、`job_id`、`report_name`。
2. UI 模块聚合维度：`event`、`session_id`、`case_id`、`step_index`、`webhook_url`。
3. 告警维度优先：
   - 执行失败：`event=job.run.failed`、`event=ui.execution.completed`（过滤 `status=failed`）。
   - 代理异常：`event=handler.http.execute.failed`、`event=ui.proxy.fetch_failed`、`event=ui.proxy.host_blocked`。
   - Webhook：`event=ui.settings.webhook_failed`。
   - 认证降级：`event=ui.execution.auth_profile_expired`、`event=ui.execution.auth_profile_not_found`、`event=headless.auth_state_invalid`、`event=ui.execution.auth_temp_write_failed`、`event=ui.execution.login_config_not_found`、`event=ui.execution.login_config_failed`。
   - 数据损坏：`event=checkpoint.corrupted`、`event=ui.proxy.session.browser_cookie_failed`。
4. 建议按 `event` 建索引并保留原始 `logger` 字段，便于跨模块追踪。
5. UI 代理链路排查链路：`ui.proxy.request_in` → `ui.proxy.session.*` → `ui.proxy.fetch_*` → `ui.proxy.page.resp_to_browser` / `ui.proxy.resource.resp_to_browser`。
