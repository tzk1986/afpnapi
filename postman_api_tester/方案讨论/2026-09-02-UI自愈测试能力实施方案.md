### 1.2 失实 / 缺漏项（本方案修正）

#### R-2【P0】事件签名 `try_heal(case_id, step_index, original_selector, page)` 在当前调用链上不成立

- **代码事实**：
  - `UiHeadlessEngine.execute()` 签名只收 `steps/base_url/options/job_id/...`（:190-200），**无 case_id**；
  - `_execute_step(page, step, base_url, timeout_ms)`（:1013）**不收 step_index**；主循环的 `i` 只在调用侧存在（:721/:758）；
  - `_find_element(page, selector, timeout_ms)`（:1297）离 action 方法两层，action 方法（如 `_action_click:1352`）全部无 step 上下文；
  - worker 子进程 `input_data` 已含 `case_data`（`ui_headless_worker.py:47`），`routes` 层持有 case_id（`ui_execution_routes.py:177/:224`）。
- **违反约束**：无（属设计缺口而非约束冲突）。
- **改进方案**：
  1. worker 把 `case_data["case_id"]` 塞进 `options`（或 `execute()` 新增 `case_id: str = ""` 关键字参数，默认空兼容），引擎实例化时存 `self._heal_ctx`；
  2. 主循环在调用 `_execute_step` 前设 `self._current_step_index = i`（执行器单用例串行，无并发污染；`execute_login_config:939` 路径同样赋值，heal 上下文置 `case_id=""` 表示登录辅助步骤）；
  3. `_find_element` 的 raise 前钩子读取 `self._heal_ctx + self._current_step_index` 组装 heal 事件；
  4. heal 结果写入 step_result 的字段统一为 `"healed"` / `"heal_info"`（见 R-8）。
- **影响风险确认**：新增实例属性不改变任何既有方法签名对外行为；`execute()` 新参数带默认值，`ui_headless_worker.py` 之外无其他调用方（grep 全仓仅 worker 与测试）。
- **规避**：单测直接构造引擎实例注入 FakePage，验证无 case_id 时 heal 仍可用（事件记 `case_id=""`），杜绝隐式 None 崩溃。

#### R-3【P0】双执行引擎：浏览器回放侧未覆盖，首版必须显式限定范围

- **代码事实**：回放选择器引擎在 JS 内（`ui_recorder_inject.py:170` `SelectorEngine`，录制生成 primary/fallback_css/fallback_xpath :186-189；回放 `_executeStep` 与其回退策略由无头侧对齐——"与浏览器引擎一致"注释 :1172/:1300）。无头引擎是 Python（`ui_headless_engine.py`，2278 行），回放引擎是注入用户浏览器的 JS（`ui_recorder_inject.py`，2568 行）。
- **违反约束**：记忆 [[feedback_tryfind_text_filter]]（M-8：JS 层改动暂缓，需回归测试）；开发阅读文档对回放引擎改动的高回归成本共识。
- **改进方案**：**首版自愈仅覆盖无头执行引擎（mode=headless）**。文档与代码 docstring 明示"浏览器回放暂不自愈"，理由三条：① JS 侧无 DOM 快照/文件写入基建，heal 事件只能回传 `/replay-log` 通道，无持久化落点；② 回放跑在用户浏览器，误修复的用户信任成本远高于无头批量跑；③ M-8 约束未解除。回放侧自愈列为二期独立评审项，不与本方案捆绑。
- **影响风险确认**：无头与回放行为将出现不对称（同一用例 headless 可能 heal、browser 失败）——这是**特性而非缺陷**（headless 定位为批量回归自愈通道），但报告页必须显示 mode（已有 :64 `"mode"` 字段），避免误读。
- **规避**：报告列表/详情页已按 mode 区分（ui_testing_reports.html），文案注明"自愈仅在无头模式生效"。

#### R-4【P1】`services/ui_self_healing/` 五模块子包违反本仓 services 扁平惯例

- **代码事实**：`services/` 下现有 ~32 个扁平文件，无任何业务子包；记忆 [[feedback_avoid_over_abstraction]]（不提取单次调用的短函数、优先模块化复用）。
- **违反约束**：同上 + 开发阅读文档分层规则。
- **改进方案**：收敛为**单文件** `services/ui_healing.py`（预计 300~400 行），内含：策略链（文本模糊→role+name→data-testid→XPath LCS）、相似度函数（stdlib）、置信度评估、`SelfHealingManager.try_heal()`、heal 事件落日志。DOM 邻域特征提取并入策略函数（R-9 后不再需要独立 snapshot 模块）。若二期膨胀超 600 行再议拆分（届时走 L-7 统一处理）。
- **影响风险确认**：新文件需登记 `pyproject.toml` `files=[`（:3 起）mypy 清单（记忆 [[feedback_deleted_handler_pyproject_cleanup]] 的反向约束：新文件必登记）。
- **规避**：实施步骤 S1.2 固化登记动作，CI mypy 兜底。

#### R-5【P1】策略④ XPath LCS 不得引入 lxml

- **代码事实**：`requirements.txt` 全仓无 lxml（grep 0 命中）。
- **违反约束**：新增生产依赖需评审（开发阅读文档依赖最小化惯例）。
- **改进方案**：结构相似度用 stdlib：`difflib.SequenceMatcher` 对"录制 fallback_xpath 的路径段序列"与"现场候选元素到 body 的路径段序列"求 LCS 比率；路径段序列从 XPath 字符串按 `/` 切分，零解析器依赖。Playwright 侧仅用 `page.evaluate` 取候选元素的 tagName/attributes/text 特征（JS 内联表达式，非注入文件改动，不受 M-8 约束）。
- **影响风险确认**：`page.evaluate` 新增调用点仅在 heal 分支（开关关时零执行），性能无回归面。
- **规避**：开关门控测试断言"ENABLE=false 时 `_find_element` 失败路径与旧行为逐字节一致"。

#### R-6【P1】配置项：无 `_env_float`，阈值改用整数百分比；双开关门控

- **代码事实**：`config.py` 仅有 `_env_bool` / `_env_int`（`UI_HEADLESS_TIMEOUT_S = _env_int(...)` :515，UI 段收尾）；不存在 `_env_float`。
- **违反约束**：记忆 [[feedback_auto_upgrade_version_rule]] 相关配置惯例、G-27"配置项定义即消费"（脚手架 v3 产出，同样适用本仓）。
- **改进方案**（追加在 `config.py` UI 段尾、`UI_HEADLESS_TIMEOUT_S` 之后）：
  ```python
  # UI 自愈（仅无头引擎；浏览器回放暂不支持）
  UI_SELF_HEALING_ENABLED = _env_bool("UI_SELF_HEALING_ENABLED", default=False)
  UI_HEALING_CONFIDENCE = _env_int("UI_HEALING_CONFIDENCE", 70, lo=10, hi=100)   # 百分比
  UI_HEALING_MAX_PER_CASE = _env_int("UI_HEALING_MAX_PER_CASE", 5, lo=1, hi=50)  # 单用例 heal 上限，防批量误修复雪崩
  ```
  三个配置在 S1 期即被 `ui_healing.py` / 引擎钩子消费，无定义即死配置。**门控**：`UI_SELF_HEALING_ENABLED and UI_HEADLESS_ENABLED` 双真才生效（worker 本身只在 headless 模式启动，此处显式短路防误开）。
- **影响风险确认**：默认 false，重启服务行为不变。
- **规避**：验收含"开关关演练"（全量回归 diff 为空）。

#### R-7【P1】误修复治理：断言类动作首版一律不自愈 + 上限熔断

- **代码事实**：`assert_not_visible`（:1901-1956）**不走** `_find_element`，天然不会触发自愈——无需豁免代码，但评审必须记录该事实防回归；走 `_find_element` 的动作含交互类（click:1355/type:1368/clear/select/hover/check）与断言类（assert_text:1462/assert_visible/assert_value/assert_enabled/assert_disabled/assert_attribute/assert_css/assert_checked）。
- **报告缺陷**：报告仅提"三重控"，未定义豁免清单；断言步骤若 heal 到相似但错误的元素，会把真 bug 洗成假通过——这是自愈功能最大的信任风险源。
- **改进方案**：
  1. **首版仅交互动作触发自愈**（click/type/clear/select/hover/check/radio 类），`action.startswith("assert")` 一律跳过（heal 分支入口一行判断）；断言自愈二期结合人工确认队列再评估；
  2. 单次执行 heal 数超 `UI_HEALING_MAX_PER_CASE` → 本用例剩余步骤禁用 heal 并在 summary 记 `heal_capped: true`（防止选择器体系整体漂移时批量假通过）；
  3. heal 成功的 step_result **永久携带** `healed: true + heal_info{old_selector, new_selector, strategy, confidence}`，报告页高亮，绝不静默。
- **影响风险确认**：豁免判断在 `UI_SELF_HEALING_ENABLED` 短路之后，开关关时零新代码路径。
- **规避**：单测断言 assert_* 动作失败时 heal 模块零调用（monkeypatch 计数）。

#### R-8【P1】结果契约贯通：`healed_steps` 需同时打通 4 层，勿只改引擎

- **代码事实**：ui_execution_routes **已完成 L-1 包装**（`BaseHandler.json_response`，:335/:369/:387/:395 等，v1.37.3 迭代产物）——新增响应字段不破坏 `{code,message,data}` 契约；`ui_execution_store.create_record` 字段固定（:54-70：case_id/mode/steps_total/steps_passed/steps_failed…），`finalize` 从 summary 合并（:182-185），`list_results` 摘要投影白名单字段（:237-243）。
- **报告缺陷**：只写"ui_execution_routes 结果增 healed_steps"，漏了 store 落盘 schema、列表投影、报告页三处。
- **改进方案**（一处不省）：
  1. 引擎 summary 增 `healed_steps: int` + `heal_events: [...]`（step_results 内各步 `healed/heal_info`）；
  2. `ui_execution_store.create_record` 初始 `healed_steps: 0`，`finalize` 合并 `summary.get("healed_steps", 0)`；
  3. `list_results/count_results` 投影增 `healed_steps`（列表页徽标）；
  4. 前端 `ui_testing_reports.html` / `ui_testing_report.html` 入口解包 `const data = raw.data || raw`（既有约定）+ 详情步骤行"已自愈"标记，错误回退链不变。
- **影响风险确认**：旧记录 JSON 文件无 `healed_steps` 字段——全部读取点必须 `.get("healed_steps", 0)`，禁止下标访问（老数据兼容）。
- **规避**：S2 门禁含"用 v1.37.x 时代旧记录渲染报告页不 KeyError"手测。

#### R-9【P0】录制期 DOM 邻域快照与 M-8 正面冲突，首版放弃

- **代码事实**：快照只能在录制时生成 = 改 `ui_recorder_inject.py`（JS 注入文件，2568 行）；记忆 M-8"JS 层改动暂缓"；`ui_case_store` 用例 JSON 无 snapshots 字段，`create_case` 也无该入参。
- **报告缺陷**：把"DOM 邻域快照"列为阶段 1 必做（且 `ui_case_store.create_case 增 snapshots_dir`），未意识到录制链路全在 JS。
- **改进方案**：首版**无录制期基线**，四级策略降级重排：
  1. 现场文本模糊（`page.get_by_text(原 selector 提取的文字特征)`）；
  2. 现场 role+name（原 selector 若为 `role=` 候选链成员）；
  3. 现场 data-testid（扫描原 xpath 末段属性继承候选）；
  4. XPath LCS：录制的 `fallback_xpath`（生成于 `ui_recorder_inject.py:188`，已在用例 JSON 里）与现场候选元素路径求结构相似度——**不需要任何新快照**。
  冷启动报告里"策略④无快照退化"问题随之消解：基线就是既有 fallback_xpath。录制期快照（提升 ④ 精度）与浏览器侧能力一并归入二期，待 M-8 解除后独立评审。
- **影响风险确认**：无新增存储物，不触碰 ui_case_store schema、不触碰录制 JS。
- **规避**：策略命中效果以单测 FakePage 验证；线上以 heal_events 日志周度复盘阈值。

#### R-10【P1】heal 持久化：首版只进诊断日志，"待确认队列"移三期

## 二、修正后架构

```
ui_execution_routes.py (持有 case_id，L-1 包装已完成)
  └─ spawn → ui_headless_worker.py (stdin JSON: case_data 含 case_id)
                └─ UiHeadlessEngine.execute(options 携 case_id)
                     └─ 主循环 self._current_step_index = i
                          └─ _execute_step → _action_xxx → _find_element
                               └─(候选链全失败, 开关开, 非 assert, 未熔断)
                                    └─ services/ui_healing.py
                                         SelfHealingManager.try_heal(page, selector, step)
                                         → 四级策略 → 置信度(≥UI_HEALING_CONFIDENCE)
                                         → 返回 (new_locator, heal_info) | None
                               └─ 命中: step_result{healed,heal_info} + 继续执行原 action
                                  事件写 logs/headless/exec_{job_id}.jsonl
                     summary{healed_steps, heal_events}
  ← worker stdout ← routes → ui_execution_store.finalize(healed_steps)
                                → /report、/reports 列表 → 前端解包 raw.data||raw 高亮"已自愈"
```

生效门控：`UI_SELF_HEALING_ENABLED(默认false) && UI_HEADLESS_ENABLED && mode==headless && 非assert动作 && heal数 < UI_HEALING_MAX_PER_CASE`。
