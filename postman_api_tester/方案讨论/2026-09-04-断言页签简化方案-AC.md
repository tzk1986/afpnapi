# 断言页签简化方案（A+C 组合，v1.38.2 提案）

- 日期：2026-09-04
- 状态：📋 方案讨论（未实施，实施待"开始实施"口令）
- 回退基线：tag `v1.38.0`（master `547de53`，已推送 origin）
- 前置依赖：**v1.38.1（P1 集合共享判定，`feature/shared-judgment-rules` `1a2b337`）先合并 master**——本方案共享列表将合并"共享断言 + 共享判定"两类，需以含 v1.38.1 的编辑器为底。

## 一、背景：复杂度根因

断言页签当前 6 个区块，是「2 执行阶段 × 3 作用域」矩阵的平铺展开：

| | 接口级 | 集合级 | 任务级（首页） |
|---|---|---|---|
| 判定层（失败短路断言） | 三态开关①＋自定义判定规则② | 集合共享判定③ | 关闭勾选＋custom_rules |
| 断言层 | 本接口断言⑤ | 集合共享断言⑥ | — |

加豁免勾选④，一屏 5 个规则列表 + 4 处长帮助文案。用户心智其实只有两问：**什么算成功**（判定）、**内容对不对**（断言）。

## 二、目标与非目标

**目标**
1. 6 区块 → **2 个规则列表 + 1 行成功标准**（模式单选 + 豁免勾选）。
2. 后端数据契约**零改动**：`x_judgment_rules` / `x_shared_judgment_rules` / `x_assertions` / `x_shared_assertions` 四键与 executor/parser/job_routes 全链路语义不变。
3. 存量集合零迁移；任务级首页入口、报告展示零回归。

**非目标**
- 不做统一 `x_verifications` 契约重构（方案 B，留作未来专项）。
- 不改 13 操作符、不改归一化口径、不改短路/联动/兜底语义。

## 三、方案 A：列表归并（纯前端）

### 3.1 行模型

前端展示行 = 存储三元组 + **仅存于浏览器内存的 `phase` 标记**（`'judgment' | 'assert'`）：

```
UIRow = { path, op, expected, phase }   // phase 不落盘
```

安全性已实证：`normalize_assertion_rules` 重建输出仅含 `{path, op, expected}`（assertions.py:88），未知键 `phase` 即使误提交也会被后端丢弃——**显示归属以"键"为唯一事实源，不依赖 phase 持久化**。

### 3.2 导入还原（读映射）

| 存储键 | 还原行标记 | 列表位置 |
|---|---|---|
| `x_judgment_rules` | judgment | 本接口规则列表，排序在前 |
| `x_assertions` | assert | 本接口规则列表，排序在后 |
| `x_shared_judgment_rules` | judgment | 集合共享规则列表，排序在前 |
| `x_shared_assertions` | assert | 集合共享规则列表，排序在后 |

### 3.3 保存拆分（写映射）

按行 `phase` 拆回两个键（AND 语义与列表顺序无关；执行时 executor 本就"任务→共享→接口"分键合并，UI 顺序不影响判定/断言阶段归属）：

```
rows.filter(phase=judgment) → x_judgment_rules（或 x_shared_judgment_rules）
rows.filter(phase=assert)   → x_assertions  （或 x_shared_assertions）
```

拆分映射表集中一处函数（如 `splitRowsByPhase(rows)`），编辑器两处（item / collection）共用。

### 3.4 布局（新）

```
┌ 本接口规则 ──────────────────────────────────────────┐
│ 成功标准: (●) 内置业务判定   ( ) 断言接管   ⓘ        │
│ ☐ 豁免集合共享规则（本接口不执行集合级两类规则）      │
│ ┌─────────────┬────┬──────────┬──────┐              │
│ │ [判定] 行…  │ op │ expected │ 删除 │ ← 失败→FAILED 且不再跑断言
│ │ [断言] 行…  │    │          │      │
│ └─────────────┴────┴──────────┴──────┘              │
│ 阶段: (断言▾) [+ 添加规则]                           │
└──────────────────────────────────────────────────────┘
┌ 集合共享规则（作用于全部接口，同上双标记列表）────────┘
```

- errCode/message 两个三态下拉收进「成功标准」行内折叠区（`⚙ 精细控制`：展开仍是继承/强制开启/强制关闭三态，供单维度关闭场景），默认不占视觉。
- 每行阶段徽标：judgment=琥珀色「判定」、assert=蓝色「断言」；行编辑下拉新增"阶段"选择（默认断言；选判定即时提示短路语义）。
- 帮助文案压缩为 3 个 tooltip（成功标准、豁免、阶段差异）。

### 3.5 方案 C：成功标准模式单选

| 模式 | 语义（等价现有操作组合） | 行为 |
|---|---|---|
| **内置业务判定**（默认） | errCode/message 继承或开启，断言为补充 | 与现状零差异 |
| **断言接管** | 勾选=本接口 `x_enable_err_code_judgment=false` + `x_enable_message_judgment=false`（三态双强制关闭） | 切换即写入双 false；若此时判定+断言两列表皆空，弹既有风格确认（沿用 v1.37.19「未配置断言近乎恒 PASSED」提示，且集合共享规则计入）；自定义判定规则不受影响照常评估（三态双关=主判定关闭态时 custom 一并跳过——**与现状一致，文案明示**） |

**模式判定（打开旧集合时回显）**：
- 双 `x_enable_*=false` → 预选「断言接管」；
- 其余（含 mixed/继承）→ 预选「内置业务判定」；
- 任务级「关闭一级判定」勾选优先（首页入口不变，页签顶注一句说明）。

## 六、风险与对策

- K-1 `phase` 标记丢失风险：normalize 丢弃未知键→**不落盘**，仅内存态；刷新/重开靠键分桶还原（§3.2），无跨会话一致性问题。
- K-2 混合列表保存拆分顺序：executor 分键消费，判定永远先于断言执行，UI 顺序变化不影响结果——用 Y-1 round-trip 钉桩兜底。
- K-3 与 v1.38.1 串行：本方案以含共享判定小节的编辑器为底，**必须等 v1.38.1 合并**后拉分支（回退点 tag `v1.38.0` 已在）。
- K-4 与 v1.39.0 脚手架（9/21）白名单交叠窗口小：本方案 1~1.5 天，9/5 前可收口，冲突概率低。
- K-5 三态"精细控制"折叠后老用户习惯：折叠区入口常驻 + tooltip，不做隐藏删除。
