### N-3【P0】healed_steps 贯通链路修正：v1 的 M5 作废，manager/routes 零改动

- **代码证据**：headless 结果持久化链为 引擎 summary → worker `_write_output`（worker:77-82）→ **`ui_execution_manager.py:275-284`（`finalize_job(job_id, status, summary)` 整包透传）** → `ui_execution_store.finalize_job`（:170-188，仅取白名单键）。routes 的 :755-765 区段是 **browser 模式** finalize（首版无浏览器自愈，数据恒为默认 0）。
- **修正**（v1 第三节文件清单 M5 **删除**，M4 扩为 store 三点）：
  1. `create_record`（store:54-70）初始 `"healed_steps": 0`；
  2. `finalize_job`（store:187 后）`record["healed_steps"] = summary.get("healed_steps", 0)`；
  3. `list_results` 投影（store:237-243）增 `"healed_steps": data.get("healed_steps", 0)`。
  manager、routes **均不改**——summary 整 dict 透传，引擎新增键天然流入。
- **影响风险**：`finalize_job` 在 manager 有 6 个异常分支以固定小 dict 调用（:122/:220/:240/:259/:295/:318/:363）——`summary.get("healed_steps", 0)` 默认路径全部安全；`get("steps_passed", ...)` 既有同款模式佐证。
- **规避**：S2.1 门禁补一条单测：manager 异常分支 finalize（无 healed_steps 键）不 KeyError。

### N-4【P0】自愈触发前置"失败分型探针"——只修"元素真不存在"

- **代码事实**：`_find_element`（:1297-1325）链耗尽抛出的异常混杂三类语义：
  ① **元素不存在**（count==0）——选择器腐化，自愈的正当目标；
  ② **存在但不可见**（timeout 内未 visible）——遮罩/时序/动画问题，heal 到别的可见元素属语义漂移（假通过源）；
  ③ **多匹配歧义**——text/role 候选未加 `.first`（`_build_locator:1198/:1201`），Playwright 对多匹配 locator 的动作/属性调用抛 strict 类异常；元素明明在，绝对不该"换元素"。
- **改进**：钩子内 raise 前加分型探针：对每个候选构建**未加 first 的裸 locator** 调 `.count()`（Playwright 非严格安全 API），
  - 任一候选 count>0 → 判定"存在但失败"（②/③类）→ **拒绝自愈**，写事件 `self_healing.rejected reason=exists_ambiguous|exists_invisible`，原异常照抛；
  - 全部候选 count==0 → "真不存在" → 进入四级策略。
  探针本身 try/except 包裹，任何探测异常 → 保守拒绝自愈（宁可漏修不可误修）。
- **理由**：这是误修复治理（R-7）的**前置闸门**，比置信度阈值更根本——阈值管"修得对不对"，分型管"该不该修"。
- **影响风险**：探针只在"链耗尽即将 raise"路径执行（开关开 + 非 assert + 未熔断），开关关零新代码路径；`.count()` 一次 RTT 开销 ≈ 毫秒级，发生在本来就该步已判死刑的时刻，不拖慢通过路径。
- **规避**：S1.3 单测三类分型各一例（FakeLocator 可编程 count 值）。

### N-5【P1】element_info 即"录制期快照"——四级策略到字段的精确映射

- **代码证据**：录制器每个步骤已持久化 `element_info{tag, text, type, href, name, placeholder, visible, aria_label, test_id}`（`ui_recorder_inject.py:434-446` `_buildElementInfo`、:473-485 `getElementInfo`，test_id 即 `data-testid`）；浏览器回放引擎已在用 `elementInfo.text` 消歧（:1099-1100，记忆 [[feedback_tryfind_text_filter]] 同源）。
- **意义**：v1 R-9 说"放弃录制期快照"，本条进一步明确——**不需要新快照，element_info 就是现成的属性指纹**，且随用例 JSON 走（无新存储）。四级策略重排为（原 v1 顺序按可得性修正）：

| 级 | 特征源（全部在用例 JSON 里） | 查找方式 | 采纳条件 | 置信度 |
|----|------------------------------|----------|----------|--------|
| ① | `element_info.test_id` | `[data-testid="…"]` | count==1 且 visible | 95 |
| ② | `primary` 的 `role=` 前缀（:1165）或 `tag→role` 映射 + `aria_label`/`text` | `get_by_role(role, name=…)` | count==1 且 visible | 85 |
| ③ | `element_info.text` | `get_by_text(text, exact=False)` 再按 `tag` 过滤 | count==1 且 visible | 75 |
| ④ | `selector.fallback_xpath`（:188 已生成） | 同 tagName 候选池（≤200，`page.evaluate` 收集），`SequenceMatcher` 路径段 LCS（R-5 stdlib） | ratio×100 ≥ 阈值且唯一最高分 | ratio×100 |
| — | element_info 缺失（手工步骤） | 仅 ④ | 同上 | — |

- **唯一性铁律**：任何级别必须 **count==1 且可见**才采纳；多匹配一律拒绝（宁漏勿误）——与回放引擎的消歧哲学一致但更保守（回放是"多匹配里挑文本"，自愈是"多匹配就不修"）。
- **置信度语义修正**：v1 的 `UI_HEALING_CONFIDENCE`（整数百分比）比较的是上表"置信度"列；①②③ 是固定分值（要么过阈值要么不过，实际等于分级开关），④ 是连续分值——阈值主要调 ④ 的松紧。
- **影响风险**：策略读取 `step.get("element_info") or {}`，对无该键的老用例自然退化到 ④，零崩溃。

### N-6【P1】登录配置链路禁止自愈

- **代码证据**：`execute_login_config()`（engine:903-939）复用 `_execute_step`，执行的是登录页交互（含 Cookie 捕获，v1.30 系列文档）。登录步骤误修复 → 会话态污染、认证文件错抓，排障成本极高。
- **改进**：引擎加实例标记 `self._healing_active`，`execute()` 置 True、`execute_login_config()` 置 False，钩子首行短路。v1 R-2 中"登录路径记 case_id=''"升级为"登录路径彻底不自愈"。
- **影响风险**：仅新增布尔短路，登录行为逐字节不变。

### N-7【P1】store.update_step 合并分支补 heal 字段（双写防丢）

- **代码证据**：manager 对 headless 步骤**双写**——实时流 `update_step`（:187/:200）+ 结束后回填重放（:279-280）；`update_step` 命中同 index 时走合并分支（store:138-145），只回写 `status/error/duration_ms/screenshot` 四字段。首写若缺、回填有，`healed/heal_info` 将丢失。
- **改进**：合并分支追加两行幂等复制：`if "healed" in step_result: existing["healed"]=…; existing["heal_info"]=…`。
- **影响风险**：白名单式扩展，其余字段行为不变。

### N-8【P2】heal 成功即时截图留证（不改前端）

- hit 后调用 `_take_screenshot(page, job_id, i, suffix="_healed")`（:777 同款签名已支持 suffix），产物存 job 目录仅作排查/三期人工确认的证据；详情页截图展示按步名精确匹配，`_healed` 后缀暂不进前端（避免 M6 范围扩张），文件留盘。
- 开关关零路径；`take_screenshots=False` 时自动跳过（沿用截图开关判断）。

### N-9【P2】防递归约束（评审检查点）

`ui_healing.py` 内**禁止**调用 `engine._find_element` / `_build_locator`（自愈策略若复用失败路径 = 递归+钩子自触发），独立裸建 locator。列为 S1 代码走查 grep 断言⑥：`_find_element` 在 ui_healing.py 中 0 命中。

### N-10【P2】开关来源单一化：只认 env，不碰 settings store

- **代码证据**：运行时存在 `_settings_store` 二次覆盖 options（routes:190/:262-267 的 br_settings/hl_settings）。
- **决策**：首版自愈开关/阈值/上限**只读 config env**（R-6 三常量），不写入 settings store、不改设置页表单——少一处 schema 变更 + 一个前端文件。三期视灰度数据再评估"设置页加自愈勾选"（届时一并评估断言动作豁免放开）。
- **理由**：自愈是高风险能力，env 级开关意味着"运维显式操作才开"，与 UI 设置页"用户随手可改"的语义分级。

### N-11【P2】测试落点修正

- **代码证据**：tests/ 无 headless 引擎专项测试文件；FakePage/FakeLocator 先例在 `test_assert_element_exists.py` 与 `test_assert_text_exists.py`（已核含 Fake 类）。
- **改进**：单文件 `tests/test_ui_healing.py` 承担两层测试：manager 纯函数级（四级策略/分型/阈值/熔断）+ 引擎钩子级（豁免/登录禁用/开关短路/无 case_id 容错），不另建第二测试文件（避免碎片化）。v1 N2 表述"复用 test_assert_element_exists 模式"维持成立。

### N-12【P2】空选择器豁免（记录在案防回归）

`_find_element` 空链直接抛 `HeadlessExecutionError("选择器为空")`（:1304-1305），先于任何候选——自愈钩子天然不触发，无需代码；单测补一例断言。

### N-13【P1→记录】iframe 边界：接受残余风险并文档化

- **代码证据**：无头定位仅覆盖主文档（page.locator/get_by_* 不穿 iframe；全仓仅 assert_text_exists 特做 all-frames 遍历，engine:1538-1558）。目标元素真身在 iframe 时表现也是"主 frame 不存在"→ N-4 分型判为可修 → 若主 frame 恰有同特征元素可能误修。
- **决策**：首版**接受**该残余风险，理由三条：① 命中需四级 + count==1 + 可见 + 阈值全过，概率低；② healed 步骤永久高亮透明（R-7）可人工识别；③ 支持 iframe 自愈需选择器带 frame path——引擎级重构，超出本方案范围，明确不做。策略 ④ 候选收集排除 `<iframe>` 内节点（evaluate 只在主文档 DOM 做，天然满足，写明防误解）。
