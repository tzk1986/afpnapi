## 三、内部接口（函数/模块契约）变更表

| 接口 | 签名变化 | 说明 |
|------|----------|------|
| `ui_healing.classify_failure(page, candidates: List[Tuple[str,str]]) -> Tuple[str, Dict[str,int]]` | 新增（纯函数，不 import playwright，page 以 `Any` 标注） | 返回 `("not_found" \| "exists" \| "unknown", {strategy: count})`；探测全程 try/except，异常归 `unknown`（保守拒绝自愈，v2 N-4） |
| `ui_healing.try_heal(page, step: Dict[str,Any], case_id: str, step_index: int) -> Optional[HealResult]` | 新增 | `HealResult` 用 `@dataclass`：`locator: Any` + `strategy: str` + `confidence: int` + `new_selector_desc: str`；内部禁调引擎 `_find_element/_build_locator`（v2 N-9） |
| `UiHeadlessEngine.__init__` | 不变 | 属性追加：`_healing_active=False`、`_heal_ctx=""`、`_current_step_index=-1`、`_heal_once: set`（T-3）、`_heal_count=0` |
| `UiHeadlessEngine.execute(options…)` | **签名不变**，读 `options.get("case_id","")`（worker 注入） | 进入置 `_healing_active=True` |
| `UiHeadlessEngine.execute_login_config` | 不变 | 进入置 `_healing_active=False`（v2 N-6） |
| `_find_element(page, selector, timeout_ms)` | **签名不变** | raise 前插钩子块（见 §四-M2）；返回 `(locator, heal_info\|None)` 的私有变体 `_find_element_for_action` 不采用——保持钩子在 `_find_element` 内、通过 `self._last_heal` 单槽回传，由 `_execute_step` catch-all 之后的正常返回路径写入 step_result |
| `store.create_record / finalize_job / update_step / list_results` | 全部签名不变 | 键增量（v2 N-3/N-7） |

> **`_find_element` → step_result 的传递设计**（走查确认的机制约束）：`_find_element` 被 ~12 个 action 方法直接调用，若改返回值要动全部 action（改动面失控）。定稿：**单槽回传**——钩子命中时 `self._last_heal = {...}`；action 方法返回的 step_result 由**主循环**（拿到 index 的唯一层，:721-778 之间、`step_result["index"] = i` 同段）统一 `step_result["healed"]=True; step_result["heal_info"]=self._last_heal` 并清槽。每步执行前置空槽，防串步。

### M1 `config.py`（UI 段尾 :515 后，+6 行）


- **规避**：三个常量 M2/M-钩子全部引用；grep 断言①（≥3 文件命中）入 S1.1 门禁。

### M2 `services/ui_headless_engine.py`（4 个插入点，净增 ≤40 行）

**a. 模块头部**（:13 后）：`from postman_api_tester.config import UI_SELF_HEALING_ENABLED, UI_HEADLESS_ENABLED, …` + `from postman_api_tester.services import ui_healing`
- **风险**：**循环 import**（ui_healing 若反向 import 引擎）｜**概率** 中（新手必踩）｜**影响** 服务起不来
- **规避**：依赖单向 engine→healing 铁律；ui_healing 不 import 引擎任何符号（page/locator 全 duck-typing）；S1.1 完成后先 `python -c "import postman_api_tester.services.ui_headless_engine"` 冒烟。

**b. `__init__` +5 属性**（见 §三）+ `execute` 首段读 options。

**c. 主循环**（:721/:754/:758 三个 `_execute_step*` 调用点之前，:763 `step_result["index"]=i` 同段）：
```python
self._current_step_index = i
self._last_heal = None
# … 调 _execute_step（含 _execute_step_monitored 路径，共用同一 i）…
if self._last_heal is not None:
    step_result["healed"] = True
    step_result["heal_info"] = self._last_heal
```
- **风险**：`_execute_step_monitored` 内部重试（:1144）→ 同步多次进钩子（T-3）｜**概率** 高（new_tab 步骤必走该路径）
- **规避**：钩子首查 `self._heal_once`（key=`(i, id(step))` 简化为 i）：该步已有 heal 判定（成功或被拒）→ 直接返回原异常不再跑策略；熔断计数只在"首次尝试"时 +1。单测：模拟重试×2 断言策略调用计数 ==1。

**d. `_find_element`（:1320-1325 raise 前）钩子块**：
```python
# 门控：env 开关 && active && 非 assert && 非空链(天然, :1304 先抛) && 未去重 && 未熔断
if (UI_SELF_HEALING_ENABLED and UI_HEADLESS_ENABLED and self._healing_active
        and not action.startswith("assert")          # ← 见下"action 来源"注
        and i not in self._heal_once
        and self._heal_count < UI_HEALING_MAX_PER_CASE):
    self._heal_once.add(i)
    kind, detail = ui_healing.classify_failure(page, candidates)   # T-4 探针
    if kind == "not_found":
        res = ui_healing.try_heal(page, self._current_step, self._heal_ctx, i)
        …置信度判定 → 命中: return res.locator（并置 _last_heal、heal_count+=1、
            self_healing.healed 事件、_take_screenshot(page, job_id, i, suffix="_healed")  # v2 N-8
        ）/ 未中: self_healing.rejected 事件
    else: self_healing.rejected reason=exists|unknown 事件
raise last_error or HeadlessExecutionError("元素未找到")   # 原样保留
```
- **走查发现的动作上下文缺口**：`_find_element` 签名里没有 action——豁免判断拿不到。三个选法：①改 `_find_element` 加 `action: str = ""` 形参（~12 个调用点全改，面大）；②引擎属性 `self._current_action`，由主循环 c 点一并设置（0 调用点改动）；③在 `ui_healing` 内不判、action 判断放钩子外层。**定稿 ②**：主循环 `self._current_action = step.get("action","")` 与 `_current_step = step` 同排设置（串行执行安全，v1 R-2 已论证单用例串行 + 子进程隔离）。
- **风险 1**：开关关时新代码路径泄漏（哪怕一次 evaluate）｜**概率** 低｜**影响** 全量回归波动
- **规避**：钩子块第一行即 env 短路（`UI_SELF_HEALING_ENABLED and …` 置于 and 链首位）；S1.2 门禁"开关关全量执行结果与 master 基线 diff 为空"。
- **风险 2**：探针 `.count()` 在 SPA 持续变更 DOM 时抖动（探测到 exists→拒 heal，恰好漏修真腐化）｜**概率** 低｜**影响** 漏修（安全侧，宁漏勿误）
- **规避**：设计接受——unknown/exists 分支留 rejected 事件，灰度期统计漏修率再议。
- **风险 3**：heal 命中返回的 locator 通过 `is_visible` 校验后、action 执行前元素被前端框架卸载（竞态）｜**概率** 低｜**影响** 该步以新错误失败（不比原失败更糟）
- **规避**：透明回写——`_last_heal` 保留 + 失败步骤截图（:770-772 既有）记录的是 heal 后的失败现场，事件含 `healed_then_failed` 标记供复盘。
- **风险 4**：引擎文件膨胀违 L-7（2278 行超长文件待拆分名单）｜**概率** 定｜**影响** 走查点名批评
- **规避**：钩子严格 ≤40 行、策略实现全在 ui_healing.py（grep 断言④"引擎含 heal 关键字行 ≤40"入 S1.2）；拆分本身不在本方案范围（防搭车重构）。

### M6 `templates/ui_testing_report.html`（**两个渲染路径，T-1**）

- **b. JS 轮询行**（:419-450 `renderStepRow` 同款函数）：`s.healed` 分支拼同一徽章 HTML。
