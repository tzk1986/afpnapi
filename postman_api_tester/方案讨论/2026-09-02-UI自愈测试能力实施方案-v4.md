## 四、门禁定义与 grep 断言全集

### 4.1 grep 断言（每个 G 全量跑一遍，任一红 → 门禁不过）

```bash

grep -rc "UI_SELF_HEALING_ENABLED\|UI_HEALING_CONFIDENCE\|UI_HEALING_MAX_PER_CASE" \
  postman_api_tester/config.py postman_api_tester/services/ui_healing.py postman_api_tester/services/ui_headless_engine.py
# ③ assert 豁免在引擎钩子内
grep -c 'startswith("assert")' postman_api_tester/services/ui_headless_engine.py   # ≥1
# ④ 引擎 heal 行 ≤40
git diff $BASE HEAD -- postman_api_tester/services/ui_headless_engine.py | grep -c '^+.*heal'   # ≤40
# ⑤ 无 lxml
grep -rn "import lxml\|from lxml" postman_api_tester/ ; test $? -ne 0
# ⑥ ui_healing 不 import 引擎/不 import manager
grep -n "ui_headless_engine\|ui_execution_manager" postman_api_tester/services/ui_healing.py   # 0 命中
# ⑦ evaluate 零字面量拼接（同行无 + 号入参）
grep -n "page.evaluate(" postman_api_tester/services/ui_healing.py | grep '+'   # 0 命中
# ⑧ 前端 heal 渲染过 escapeHtml
grep -c "escapeHtml" templates/ui_testing_report.html   # 新增行内命中
# ⑨ ui_healing 顶层禁 playwright（TYPE_CHECKING 块除外）
grep -n "^from playwright\|^import playwright" postman_api_tester/services/ui_healing.py   # 0 命中
```

## 六、偏离处理 SOP（本 v4 的核心条款——"修复问题不得改变方案"）

### 6.1 问题三分类（遇到任何修不动/发现 bug，先分类再动手）

```
问题出现
 ├─ A 类｜实现缺陷：bug 在 v3 §四 所列文件内、修法在签名契约与白名单内
 │        → 正常修复，commit message `自愈(S#.#)-fix: <根因>`，重跑该步验证
 ├─ B 类｜方案缺口：修复需要 → ①新建第 4 个文件 ②移动/改目录结构 ③改白名单外文件
 │        ④改任何现有函数签名 ⑤动红线文件 ⑥改变 v3 已定的字段/事件命名
 │        → 【停止编码】。在本文附录 B《偏离登记表》填一行：现象/影响/2 个以上选项/建议；
 │          用户确认 → 把裁决写回 v3/v4 对应条款（修订留痕）→ 白名单扩容 → 才恢复编码。
 │          禁止"先改了再补文档"。
 └─ C 类｜路过问题：非 UI 链路既有 bug、顺手可优化点
          → 记入附录 C《后续问题清单》，当场不修（防搭车重构），合并后转每晚升级任务或独立方案。
```

### 6.2 硬纪律（沿用脚手架 v5 并加码）

1. **单步失败 3 次 → 停 → 回读** v3 §四 对应 M 节 + v2 对应 N 节，仍无解 → 按 B 类登记。禁止第 4 次"换个思路试试"式现场发挥。
2. **红灯不回望**：门禁（§四）任何一项红了，只允许"把代码改回符合门禁"，不允许"改门禁/删断言/放宽阈值让它过"——门禁条款变更等同于 B 类。
3. **每日收工对照**：`git diff --name-only $BASE HEAD` 与 §2.1 白名单人工比对一次；发现清单外文件 → 当日任务停下先处置。
4. **修复 commit 必须自证分类**：message 含 A/B/C 类别标记（如 `自愈(S1.4)-fix: ...`），B 类必须先有附录 B 编号。
5. **不制造第二真源**：实施中对 v3 的任何细化只写进本文档（及其附录），禁止新开散落的 `notes.md`/注释长文。

### 6.3 目录结构专项保护（用户点名关切）

- `services/` 保持扁平：验收 = `find postman_api_tester/services -type d` 仅输出 `services` 本身（无新子目录）。
- 自愈逻辑物理位置唯一：`ui_healing.py`（策略）+ 引擎 ≤40 行钩子；任何"把策略搬回引擎/搬去 utils"的冲动 = B 类。
- 模板、tests、日志目录均不新增子目录。
