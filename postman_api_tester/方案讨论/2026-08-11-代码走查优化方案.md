## 二、严重问题（必须整改）

### C-1：`_active_jobs` 并发竞争 — 无锁访问

**文件**：`handlers/ui_execution_routes.py` 第 36 行、`services/ui_execution_manager.py` 第 26 行

```python
_active_jobs: Dict[str, Dict[str, Any]] = {}  # 无任何锁保护
```

**问题**：该字典在 Flask 多线程请求中被读写（写入、遍历、pop、len 检查），存在 `RuntimeError: dictionary changed size during iteration` 风险。

**整改方案**：
- 添加 `threading.Lock()` 或使用 `threading.RLock()` 保护所有访问
- 考虑使用 `dict.copy()` 快照替代直接遍历

### C-2：`report_server.py` 业务逻辑泄漏 — `ui_testing_spa_resource_fallback()`

**文件**：`postman_api_tester/report_server.py` 第 702-1007 行（~300 行）

**问题**：该函数包含 URL 解析、SPA 资源检测、代理 session 管理、Token 跨域传递、HTML/CSS 改写等大量业务逻辑，严重违反"报告服务仅保留装饰器+单行委托"约束。

**整改方案**：
- 将函数体整体迁移至 `handlers/ui_testing_routes.py` 或新建 `handlers/ui_spa_routes.py`
- `report_server.py` 中仅保留一行委托调用
- 涉及的子逻辑（session 查找、Token 继承、代理转发）已在 `ui_proxy_service.py` 有实现，应复用

### C-3：`core/variable_context.py` 跨层引用 services

**文件**：`postman_api_tester/core/variable_context.py` 第 81、116 行

```python
from postman_api_tester.services.global_variables_service import (_read_store, _write_store)
from postman_api_tester.services.global_variables_service import (merge_variables_for_env)
```

**问题**：`core/` 层禁止引用 `services/`，违反分层规则。

**整改方案**：
- 将 `_read_store`/`_write_store` 的文件 I/O 部分抽取为 `utils/variable_store_utils.py` 中的纯函数
- `VariableContext.save_to_file()` / `load_from_file()` 改为调用 utils 函数
- `merge_variables_for_env` 移到 `utils/variable_substitution.py` 或作为 `VariableContext` 实例方法

## 三、高优先级问题

### H-1：SSRF 防护缺省 — 代理端点默认允许所有主机

**文件**：`handlers/test_proxy_routes.py` 第 71 行、`handlers/ui_testing_routes.py` 第 123 行

```python
def _check_proxy_host_allowed(url: str) -> ResponseReturnValue | None:
    if not PROXY_ALLOWED_HOSTS:
        return None  # 空配置 = 无限制
```

**问题分析**：

`PROXY_ALLOWED_HOSTS` 未配置时，代理端点允许请求任意 URL，包括内网地址。`is_safe_url()` 工具函数已存在但未被调用。

**⚠️ 关键风险评估（v1.30.114 历史教训）**：

v1.30.114 曾在 `ui_proxy_service.py::fetch_and_rewrite()` 中加入 `is_safe_url()` 检查，**导致所有内网系统回放全部 404**。原因：UI 代理的核心用途就是转发到用户配置的内网系统（如 `10.50.11.120:9011`），SSRF 防护与业务需求直接冲突。v1.30.117 已移除该检查。

**影响链路分析**：

| 端点 | 用途 | 是否允许内网 IP | 添加 `is_safe_url()` 的影响 |
|------|------|----------------|---------------------------|
| `/ui-testing/proxy` | 浏览器回放主代理 | **必须允许** | ❌ 阻断所有内网系统回放，new_tab 跳转失败 |
| `/ui-testing/proxy-resource` | 回放资源代理（CSS/JS/图片） | **必须允许** | ❌ 阻断内网系统资源加载 |
| `/re-request-api` | API 测试重发 | 视用户需求 | ⚠️ 可能阻断内网 API 测试 |
| `/api/proxy-request` | API 测试代理 | 视用户需求 | ️ 可能阻断内网 API 测试 |

**结论**：**UI 代理端点禁止添加 `is_safe_url()` 检查**。

**整改方案**（修正）：

1. **UI 代理端点（`ui_testing_routes.py`）**：**不做任何修改**。现有行为（`PROXY_ALLOWED_HOSTS` 为空时允许所有主机）是正确的设计，满足内网系统回放需求。

2. **测试代理端点（`test_proxy_routes.py`）**：保持现有行为不变。如果用户需要 SSRF 防护，应通过配置 `PROXY_ALLOWED_HOSTS` 白名单实现，而非默认拒绝策略。

3. **文档补充**：在 `开发阅读文档.md` 中明确记录"UI 代理链路禁止套用 `is_safe_url()`"的约束，避免后续开发者再次踩坑。

**Why:** 用户明确指出之前因 SSRF 检查导致 new_tab 跳转失败的 bug，要求排查修改是否会影响现有功能。经分析，UI 代理端点必须允许内网 IP，添加 `is_safe_url()` 会直接阻断浏览器回放功能。

### H-2：Cookie 明文写入日志 — 敏感数据泄露

**文件**：`handlers/ui_testing_routes.py` 多处（第 277、325、414、432、557、666、846 行）

```python
"browser_cookies": dict(request.cookies)  # 包含 JSESSIONID、auth token 等
```

**问题**：浏览器完整 Cookie 以明文写入日志文件，包含会话令牌、认证信息等敏感数据。

**整改方案**：
- 日志中使用 `security.sanitize_headers()` 或自定义 `sanitize_cookies()` 对 Cookie 值做掩码处理
- 仅记录 Cookie 名称和长度，不记录完整值：`"JSESSIONID=*** (32 chars)"`

### H-3：handlers 直接文件 I/O — 分层违规

**文件**：
- `handlers/job_routes.py` 第 373-374 行：`saved_file.open("w")` + `json.dump()`
- `handlers/collection_routes.py` 第 174-176 行：`export_path.open("rb")`
- `handlers/collection_editor_routes.py` 第 28-29 行：`file.read().decode("utf-8")`

**问题**：`handlers/` 层禁止直接操作文件系统，应通过 `services/` 或 `utils/` 处理。

**整改方案**：
- 将文件读写逻辑封装到 `services/collection_file_service.py`（新建）
- handler 中仅保留参数校验和委托调用

### H-4：`_get_proxy_session_id()` 过长函数 — 280 行，5+ 层嵌套

**文件**：`handlers/ui_testing_routes.py` 第 136-417 行

**问题**：处理 session 复用、跨域 session 匹配、Cookie 继承、Token 传递、Referer 解析、新 session 创建等，可读性和可测试性极差。

**整改方案**：拆分为多个独立函数：
- `_find_existing_session(referer_url, browser_cookies)` — 查找已有 session
- `_create_new_session()` — 创建新 session
- `_handle_cross_origin_session(new_base_url, old_sessions)` — 跨域 Token 继承
- `_build_session_cookie(session_id)` — 构建响应 Cookie

### H-5：`ui_testing_proxy()` 职责过重 — 250 行

**文件**：`handlers/ui_testing_routes.py` 第 420-670 行

**问题**：混合了 URL 解析、模式检测、session 管理、HTTP 请求、响应改写、Cookie 处理等多种职责。

**整改方案**：拆分为：
- `_prepare_proxy_context(url, mode)` — URL 解析 + 模式检测
- `_execute_proxy_request(session, target_url)` — HTTP 请求执行
- `_build_proxy_response(response, session)` — 响应改写 + Cookie 构建

每个端点都重复相同的三层异常处理结构（FileNotFoundError → 404、ValueError → 400、Exception → 500）。

**整改方案**：引入 `@require_global_variables_enabled` 装饰器。

### M-8：录制器事件监听泄漏

**文件**：`services/ui_recorder_inject.py`

- `setInterval(_processEventQueue, 100)` 录制停止后仍在运行
- `window` + `document` + `document.body` 重复注册相同事件类型的监听器（12+ 个）
- 早期脚本和主脚本双重事件捕获路径导致步骤重复录制

**整改方案**：
- 录制停止时 `clearInterval()`
- 移除 `document` 和 `document.body` 上的重复监听器
- 统一事件捕获路径（仅使用早期脚本的队列机制）

### M-9：回放引擎 NetworkComparator 在代理上下文中失效

**文件**：`services/ui_recorder_inject.py` 第 1158-1229 行

网络比对器拦截 fetch 时获取的是改写后的代理 URL（`/ui-testing/proxy-resource?url=...`），而非原始目标 URL，导致路径匹配永远失败。

**整改方案**：
- 比对器应从原始 fetch 调用的第一个参数提取目标 URL（在 proxy 改写之前）
- 或在代理改写时通过 `X-Original-Url` 响应头传递原始 URL 供比对器使用

### M-10：录制会话仅内存存储，服务重启丢失

**文件**：`handlers/ui_testing_routes.py` 第 30-83 行

**整改方案**：
- 将 `_RecordingSession` 迁移到 `services/ui_recording_store.py`
- 添加定期 JSON 持久化（如每 30 秒写入一次）
- 服务启动时从磁盘恢复未完成会话

### M-11：UI 执行结果无定期自动清理

`UiExecutionStore.cleanup_expired()` 仅通过 API 手动触发，无定时任务。

**整改方案**：在服务启动时注册后台线程，每小时检查并清理超过保留天数的执行记录。

## 五、低优先级问题

### L-1：`BaseHandler.json_response()` 未被统一使用

10+ 个 handler 文件直接使用 `jsonify()` 而非 `BaseHandler.json_response()`，导致响应格式不一致。

**整改方案**：逐步统一为 `BaseHandler.json_response()`，确保所有 JSON 响应都有 `{code, message, data, timestamp}` 结构。

### L-2：`get_report_or_error` 返回类型为 `Any`

**文件**：`handlers/base_handler.py` 第 195 行

应标注为 `Union[Dict[str, Any], ResponseReturnValue]` 或改为抛出异常。

### L-3：硬编码魔法数字

| 位置 | 值 | 建议 |
|------|-----|------|
| `ui_testing_routes.py` 第 449 行 | `5` | 提取为 `MAX_PROXY_UNWRAP_DEPTH` |
| `ui_testing_routes.py` 第 654 行 | `3600` | 提取为 `PROXY_COOKIE_MAX_AGE` |
| `ui_execution_routes.py` 第 727 行 | `10` | 提取为 `WEBHOOK_TIMEOUT` |
| `server_routes.py` 第 450/476 行 | `5000` | 提取为 `DEFAULT_PORT` |

### L-4：命名约定不一致

- `get`/`find`/`load`/`read` 混用表示查询操作
- `api_collection_parse`/`api_collection_save` 使用非标准动词
- `api_report_result_judgement` 使用名词而非动词

**整改方案**：制定命名约定文档，迭代修正。优先统一 `get_*`（单个）/ `list_*`（列表）/ `load_*`（持久化加载）。

### L-5：`Dict[str, Any]` 过度使用

核心数据结构（报告记录、执行结果、用例数据）均使用 `Dict[str, Any]`，无法利用 IDE 补全和静态检查。

**整改方案**：为关键数据结构引入 `TypedDict`：
- `ReportResultDict`（报告结果条目）
- `ExecutionStepDict`（执行步骤）
- `UITestCaseDict`（UI 用例）

### L-6：Jinja2 `autoescape=False`

**文件**：`core/html_reporter.py` 第 32 行

当前数据流安全（数值+转义），但关闭 autoescape 增加了未来引入 XSS 的风险。

**整改方案**：改为 `autoescape=True`，对需要原始 HTML 的字段显式使用 `|safe` 并确保数据可信。

### L-7：超长文件需拆分

| 文件 | 行数 | 建议 |
|------|------|------|
| `services/ui_recorder_inject.py` | 2134 | JS 模板字符串为主，可接受 |
| `services/ui_proxy_service.py` | 1868 | 可拆分为 `proxy_service.py` + `proxy_html_rewriter.py` |
| `services/ui_headless_engine.py` | 1256 | 可拆分为 `headless_engine.py` + `headless_newtab.py` |
| `handlers/ui_testing_routes.py` | 1176 | 拆为 `ui_testing_routes.py` + `ui_proxy_routes.py` + `ui_recording_routes.py` |

### L-8：`ui_proxy_service.py` 中中文登录检测启发式

**文件**：`ui_headless_engine.py` 第 698 行

```python
if "登" in sel_str and "录" in sel_str:
```

依赖中文字符判断登录按钮，国际化场景下会失效。

**整改方案**：改为基于步骤元数据（如 `step.is_login_step`）或选择器类型判断。

## 七、影响分析与安全实施保障

### 7.1 各改动项对现有功能的影响评估

#### C-1：`_active_jobs` 加锁

**影响评估：安全 ✅**

- 两个 `_active_jobs` 是独立模块级变量（`ui_execution_routes.py` 管理 browser_replay，`ui_execution_manager.py` 管理 headless），互不干扰
- `ui_execution_manager.py` 的 `_active_jobs` **已加锁**，运行稳定无问题报告
- 新增锁与现有锁完全独立，无嵌套关系，**不会死锁**
- 锁持有时间微秒级（O(1) 字典操作），并发上限 5，**性能影响可忽略**
- **风险点**：`_cleanup_stale_jobs()` 的遍历+pop 需在同一个锁内完成；`len()` 检查与写入需合并到同一锁块（防止 TOCTOU 竞态）

#### C-2：`report_server.py` 业务逻辑迁移

**影响评估：安全 ✅**

- 迁移到 `ui_testing_routes.py` 后，路由注册保持薄包装模式，URL 不变
- `_get_proxy_session_id` 跨文件懒加载变为同模块调用，**正向优化**
- Logger 名称会从 `report_server` 变为 `handlers.ui_testing_routes`，日志 `event` 字段不受影响
- **风险点**：迁移后需确认 `request`、`make_response`、`abort` 等 Flask 对象在新模块可用（已有导入，无风险）
- **关键验证**：new_tab 跳转链路（SPA fallback → session 复用 → proxy 转发）不受影响

#### C-3：`core/variable_context.py` 跨层引用修复

**影响评估：安全 ✅**

- 现有 48 个测试用例（15+33）提供充分安全网
- `VariableContext` 的公开 API 完全不变，调用方（`postman_api_tester.py`、测试文件）零改动
- 变量提取链（`update_from_extract`）、变量替换（`substitute_in_api_config`）完全在 core/utils 层，不依赖 services
- **关键约束**：`services/global_variables_service.py` 中 20+ 处调用 `_read_store`/`_write_store`，需同步更新 import 路径
- **风险点**：`merge_variables_for_env` 在测试中被直接导入，需在 services 层保留 re-export 保持向后兼容

#### H-2：Cookie 日志脱敏

**影响评估：安全 ✅**

- 8 处 `dict(request.cookies)` 记录均为调试诊断日志，无监控告警依赖
- 现有代码已有多处部分脱敏先例（JSESSIONID 截断 20 字符、Cookie 值截断 30 字符）
- 脱敏后仍保留 Cookie 名称和长度，足以诊断 session 匹配/丢失问题
- **注意**：`security.sanitize_headers()` 不适合处理 Cookie 字典（键是 Cookie 名称而非 HTTP 头名），需新增专用 `sanitize_cookies()` 函数
- **项目规范依据**：《日志字段规范》v1.3.0 第 3.1 条明确"禁止记录 Cookie 明文值"

#### H-3：handlers 文件 I/O 下沉

**影响评估：安全 ✅**

- 关键路径构建函数 `_build_saved_json_path` 已在 services 层，下沉不改变路径生成逻辑
- 导出文件写入已在 `report_export_service.py`，handler 只做流式读取，下沉仅移动代码位置

- **风险点**：流式导出必须保持 generator 惰性求值模式（64KB 分块），否则大文件内存溢出
- **建议顺序**：先下沉 `collection_editor_routes.py:28-29`（风险最低），再 `job_routes.py:373-374`，最后 `collection_routes.py:174-176`

#### H-4/H-5：过长函数拆分

**影响评估：需严格按顺序执行 ⚠️**

**`_get_proxy_session_id()` 拆分（H-4）**：
- 4 个调用方：`ui_testing_proxy()`、`ui_testing_proxy_resource()`、`ui_testing_static_fallback()`、`report_server.py::ui_testing_spa_resource_fallback()`
- **必须保留的核心行为**：Cookie 查找 session（步骤 C）、跨域 origin 匹配（步骤 D）、Referer 回退查找（步骤 G，**new_tab 关键**）、JSESSIONID 加载（步骤 J）、Token 继承（步骤 I）
- **遗漏后果**：丢失步骤 G → new_tab 跳转后无法复用已有 session；丢失步骤 J → 新 session 不带认证 cookie，目标服务器返回登录页
- **建议**：先拆分 H-4 作为独立 session 管理模块，再拆分 H-5

**`ui_testing_proxy()` 拆分（H-5）**：
- 路由注册不变，仅函数体拆分
- **关键风险**：嵌套代理解包（步骤 4）中 `target_url` 变量原地修改，拆分子函数后需确保返回值正确传递
- **关键风险**：`_set_cookies` 特殊 key 的处理（步骤 16），拆分后必须确保正确传递
- **关键风险**：`replay_mode` 和 `replay_engine_js` 参数必须正确传递到 `UiProxyService.fetch_and_rewrite()`，否则回放引擎不注入

### 7.2 实施安全原则

1. **每项改动独立提交**：便于回退和定位问题

3. **优先改动测试覆盖充分的模块**：C-3（48 个测试）、H-2（测试易补充）
4. **H-4/H-5 严格按顺序**：先拆分 `_get_proxy_session_id()`，再拆分 `ui_testing_proxy()`
