# 网络请求捕获链路补全方案

**版本基线**：v1.33.1
**日期**：2026-08-11
**关联问题**：代码走查 M-9（NetworkComparator 在代理上下文中失效）

---

## 一、问题背景

回放引擎内置了 `NetworkComparator`，用于在回放时对比"实际发出的网络请求"与"录制时的请求"是否一致。若发现差异（请求头变化、状态码不同），会在回放日志中报告 `network_mismatch`。

**当前状态：NetworkComparator 形同虚设。**

原因有二：

1. **录制时不捕获网络数据**：fetch 拦截只记录了 URL 和方法，没有请求头、请求体、响应状态码。步骤中不存在 `network_request` / `network_response` 字段。
2. **回放时 URL 匹配失败**：回放走代理，fetch/XHR 拦截到的是代理 URL（`/ui-testing/proxy-resource?url=...`），而录制存的是原始 URL，路径完全对不上。

---

## 二、现有数据流分析

### 2.1 录制阶段

```
页面 fetch(url, opts)
  → 注入脚本拦截
  → sendEvent({ action: 'api_call', value: url, element_info: { tag: 'fetch', method } })
  → postMessage 到父页面
  → 父页面 steps.push(step)       ← step 只有 url/method，无请求头/响应
  → 同时 POST /api/ui-testing/recording/step 存入会话
```

**缺失**：
- 请求头（`opts.headers`）未捕获
- 请求体（`opts.body`）未捕获
- 响应状态码/头/体未捕获（响应异步返回，`sendEvent` 不等响应）
- XHR 请求完全未发送 `api_call` 事件

### 2.2 回放阶段

```
api_ui_testing_execution_init(job_id)
  → _extract_network_requests(steps)   ← 查找 step.network_request，永远为空
  → 返回 network_requests: []
  → 回放页面传给 ReplayEngine.init
  → NetworkComparator.init([])         ← recorded 为空，不安装拦截器
  → 回放期间不做任何网络对比
```

### 2.3 `_extract_network_requests` 期望的数据结构

```python
step = {
    "action": "api_call",
    "network_request": {
        "url": "http://target/api/data",
        "url_path": "/api/data",
        "method": "POST",
        "headers": {"Content-Type": "application/json"},
        "body": '{"key": "value"}'
    },
    "network_response": {
        "status": 200,
        "body": '{"result": "ok"}'
    }
}
```

---

## 三、改动方案

### 3.1 总体思路

采用**两阶段事件**模式：

1. **请求阶段**（同步）：fetch/XHR 调用时立即发送 `api_call` 事件，包含请求数据和唯一 ID
2. **响应阶段**（异步）：响应返回后发送 `api_response` 事件，通过 ID 关联到对应请求

这样保证即使响应未返回（页面跳转、超时），请求数据也不会丢失。

### 3.2 改动一览

| 文件 | 改动内容 | 风险 |
|------|---------|------|
| `services/ui_recorder_inject.py` | fetch 拦截增强：捕获请求头/体 + 响应数据 | 中 |
| `services/ui_recorder_inject.py` | XHR 拦截增强：发送 api_call 事件 + 捕获响应 | 中 |
| `services/ui_recorder_inject.py` | NetworkComparator `_getPath` 修复代理 URL 解析 | 低 |
| `templates/ui_testing_recorder.html` | 处理 `api_response` 事件，回填响应数据 | 低 |
| 后端 Python | **无需改动** | 无 |

### 3.3 详细设计

#### 3.3.1 注入脚本 — fetch 拦截增强

**位置**：`ui_recorder_inject.py` 第 836-851 行

**改动前**：
```javascript
window.fetch = function(url, opts) {
    if (_shouldProxy(url)) {
      arguments[0] = _toProxyUrl(typeof url === 'string' ? url : String(url));
    }
    if (recording && url && typeof url === 'string') {
      sendEvent({
        action: 'api_call',
        selector: null,
        value: url,
        element_info: { tag: 'fetch', method: (opts && opts.method) || 'GET' },
        page_url: location.href,
        page_title: document.title
      });
    }
    return origFetch.apply(this, arguments);
};
```

**改动后**：
```javascript
var _netIdCounter = 0;

window.fetch = function(url, opts) {
    var origUrl = typeof url === 'string' ? url : (url && url.href ? url.href : String(url));
    if (_shouldProxy(origUrl)) {
      arguments[0] = _toProxyUrl(origUrl);
    }
    if (recording && origUrl) {
      var netId = ++_netIdCounter;
      var method = (opts && opts.method) || 'GET';
      // 提取请求头
      var reqHeaders = {};
      if (opts && opts.headers) {
        try {
          if (typeof opts.headers.forEach === 'function') {
            opts.headers.forEach(function(v, k) { reqHeaders[k] = v; });
          } else if (typeof opts.headers === 'object') {
            for (var k in opts.headers) {
              if (opts.headers.hasOwnProperty(k)) reqHeaders[k] = opts.headers[k];
            }
          }
        } catch(e) {}
      }
      // 提取请求体
      var reqBody = '';
      if (opts && opts.body) {
        try {
          reqBody = typeof opts.body === 'string' ? opts.body : JSON.stringify(opts.body);
          if (reqBody.length > 4096) reqBody = reqBody.substring(0, 4096) + '...(truncated)';
        } catch(e) {}
      }
      // 提取路径
      var urlPath = '';
      try { urlPath = new URL(origUrl, location.href).pathname; } catch(e) {}

      sendEvent({
        action: 'api_call',
        selector: null,
        value: origUrl,
        element_info: { tag: 'fetch', method: method },
        page_url: location.href,
        page_title: document.title,
        _net_id: netId,
        network_request: {
          url: origUrl,
          url_path: urlPath,
          method: method,
          headers: reqHeaders,
          body: reqBody
        }
      });

      // 异步捕获响应
      var result = origFetch.apply(this, arguments);
      result.then(function(resp) {
        try {
          var respBody = '';
          var contentType = resp.headers.get('content-type') || '';
          if (contentType.indexOf('json') >= 0 || contentType.indexOf('text') >= 0) {
            resp.clone().text().then(function(text) {
              respBody = text;
              if (respBody.length > 4096) respBody = respBody.substring(0, 4096) + '...(truncated)';
              _sendResponseUpdate(netId, resp.status, respBody);
            }).catch(function() {});
          } else {
            _sendResponseUpdate(netId, resp.status, '');
          }
        } catch(e) {}
        return resp;
      }).catch(function() {});
      return result;
    }
    return origFetch.apply(this, arguments);
};
```

**关键设计决策**：
- 请求体截断 4KB：防止大文件上传数据撑爆会话存储
- 响应体截断 4KB：同上
- 只对 `json`/`text` 类型读取响应体：避免对二进制内容（图片、PDF）调用 `.text()`
- `resp.clone()` 后读取：不影响原始响应的消费

#### 3.3.2 注入脚本 — XHR 拦截增强

**位置**：`ui_recorder_inject.py` 第 854-869 行

**改动前**：XHR 只改写 URL，不发送录制事件。

**改动后**：
```javascript
var _OrigXHR = window.XMLHttpRequest;
var origOpen = _OrigXHR.prototype.open;
var origSend = _OrigXHR.prototype.send;

_OrigXHR.prototype.open = function(method, url) {
    this._uiRecorderMethod = method;
    this._uiRecorderUrl = url;
    return origOpen.apply(this, arguments);
};

_OrigXHR.prototype.send = function(body) {
    var url = this._uiRecorderUrl;
    var method = this._uiRecorderMethod || 'GET';

    if (_shouldProxy(url)) {
      var proxyUrl = _toProxyUrl(typeof url === 'string' ? url : String(url));
      origOpen.call(this, method, proxyUrl);
    }

    // 录制 api_call 事件
    if (recording && url && typeof url === 'string') {
      var xhr = this;
      var netId = ++_netIdCounter;
      var urlPath = '';
      try { urlPath = new URL(url, location.href).pathname; } catch(e) {}
      var reqBody = '';
      try {
        reqBody = typeof body === 'string' ? body : (body ? JSON.stringify(body) : '');
        if (reqBody.length > 4096) reqBody = reqBody.substring(0, 4096) + '...(truncated)';
      } catch(e) {}

      sendEvent({
        action: 'api_call',
        selector: null,
        value: url,
        element_info: { tag: 'xhr', method: method },
        page_url: location.href,
        page_title: document.title,
        _net_id: netId,
        network_request: {
          url: url,
          url_path: urlPath,
          method: method,
          headers: {},
          body: reqBody
        }
      });

      // 异步捕获响应
      xhr.addEventListener('loadend', function() {
        try {
          var respBody = xhr.responseText || '';
          if (respBody.length > 4096) respBody = respBody.substring(0, 4096) + '...(truncated)';
          _sendResponseUpdate(netId, xhr.status, respBody);
        } catch(e) {}
      });
    }

    return origSend.apply(this, arguments);
};
```

**注意**：XHR 的 `setRequestHeader` 在 `open()` 和 `send()` 之间调用，拦截时机复杂。此处暂不捕获 XHR 请求头（`headers: {}`），后续版本可增强。

#### 3.3.3 响应回填辅助函数

在注入脚本中添加：

```javascript
function _sendResponseUpdate(netId, status, body) {
    if (!recording) return;
    sendEvent({
      action: 'api_response',
      _net_id: netId,
      network_response: {
        status: status,
        body: body
      }
    });
}
```

#### 3.3.4 父页面处理 `api_response` 事件

**位置**：`templates/ui_testing_recorder.html` 第 285-339 行

在现有的 `message` 事件监听器中，增加对 `api_response` 事件的处理：

```javascript
if (e.data.type === 'ui-recorder-event') {
    if (!recording) return;
    var step = e.data.data;

    if (step.action === 'api_response' && step._net_id) {
      // 回填响应数据到对应的 api_call 步骤
      var netId = step._net_id;
      for (var i = steps.length - 1; i >= 0; i--) {
        if (steps[i].action === 'api_call' && steps[i]._net_id === netId) {
          steps[i].network_response = step.network_response;
          break;
        }
      }
      // 同步到服务端会话（可选）
      if (sessionId) {
        fetch('/api/ui-testing/recording/step', {
          method: 'POST',
          headers: { 'Content-Type': 'application/json' },
          body: JSON.stringify({
            session_id: sessionId,
            step: step,
            is_response_update: true
          })
        });
      }
      return;
    }

    // 原有的 api_call 等其他事件处理逻辑不变
    steps.push(step);
    // ...
}
```

**注意**：`api_response` 不会被 push 到 steps 数组，只用于回填已有步骤的响应数据。

#### 3.3.5 后端会话存储适配

**位置**：`handlers/ui_testing_routes.py` 的 `api_ui_testing_recording_step`

需要处理 `is_response_update: true` 的请求——不新增步骤，而是找到已有步骤并更新：

```python
def api_ui_testing_recording_step() -> ResponseReturnValue:
    payload = request.get_json(silent=True)
    if not payload:
        return json_error("无效的 JSON 数据", 400, "UIT_REC_001")

    session_id = payload.get("session_id", "")
    step = payload.get("step", {})
    is_response_update = payload.get("is_response_update", False)

    if not session_id:
        return json_error("缺少 session_id", 400, "UIT_REC_002")

    if is_response_update:
        # 回填响应数据到已有步骤
        net_id = step.get("_net_id")
        if net_id:
            _recording.update_step_response(session_id, net_id, step.get("network_response", {}))
        return BaseHandler.json_response({"ok": True})

    idx = _recording.add_step(session_id, step)
    if idx is None:
        return json_error(f"录制会话不存在: {session_id}", 404, "UIT_REC_003")

    return BaseHandler.json_response({"ok": True, "step_index": idx})
```

**位置**：`services/ui_recording_store.py`

新增 `update_step_response` 方法：

```python
def update_step_response(self, session_id: str, net_id: int, network_response: dict) -> bool:
    """根据 _net_id 回填 api_call 步骤的响应数据。"""
    with self._lock:
        session = self._sessions.get(session_id)
        if not session:
            return False
        for step in reversed(session["steps"]):
            if step.get("action") == "api_call" and step.get("_net_id") == net_id:
                step["network_response"] = network_response
                return True
    return False
```

#### 3.3.6 NetworkComparator 代理 URL 修复

**位置**：`ui_recorder_inject.py` 第 1210-1217 行

**改动前**：
```javascript
_getPath: function(url) {
    try {
      var u = new URL(url, location.href);
      return u.pathname;
    } catch(e) {
      return url;
    }
},
```

**改动后**：
```javascript
_getPath: function(url) {
    try {
      // 从代理 URL 中提取原始 URL
      var actualUrl = url;
      if (url.indexOf('/ui-testing/proxy-resource') !== -1) {
        var qIdx = url.indexOf('?url=');
        if (qIdx !== -1) {
          actualUrl = decodeURIComponent(url.substring(qIdx + 5));
        }
      }
      var u = new URL(actualUrl, location.href);
      return u.pathname;
    } catch(e) {
      return url;
    }
},
```

这样回放时，代理 URL `/ui-testing/proxy-resource?url=http%3A%2F%2Ftarget%2Fapi%2Fdata` 会被解析为 `http://target/api/data`，路径 `/api/data` 就能与录制时的原始路径正确匹配。

## 四、兼容性保障

### 4.1 已有用例不受影响

- 旧用例的 `api_call` 步骤没有 `network_request` 字段
- `_extract_network_requests` 对这些步骤直接 `continue`（行为与当前一致）
- NetworkComparator 在 `recorded` 为空时不安装拦截器（行为与当前一致）

### 4.2 录制页面兼容

- 旧的 `sendEvent` 调用（click、wait 等）不含 `_net_id`，不受影响
- 新增的 `api_response` 事件对旧版注入脚本透明（旧版不发送此事件）

### 4.3 回放引擎兼容

- 新增的 `_getPath` 代理 URL 解析对非代理 URL 无影响（`indexOf` 检查确保只对代理 URL 生效）
- NetworkComparator 的 `_onRequest` 逻辑不变，只是匹配准确性提升

### 4.4 性能考量

| 方面 | 影响 | 缓解措施 |
|------|------|---------|
| 响应体读取 | `resp.clone().text()` 有额外 I/O | 仅对 json/text 类型读取 |
| 会话存储大小 | 每个 api_call 多了请求头/体/响应 | 请求体和响应体均截断 4KB |
| postMessage 频率 | 每个 api_call 多一条 api_response | 仅录制模式下发送 |

## 七、不在本次范围内

- **请求头完整捕获**：XHR 的 `setRequestHeader` 拦截需要额外 monkey-patch，暂不实现
- **响应头捕获**：NetworkComparator 当前只比对状态码，不比对响应头
- **WebSocket 捕获**：WebSocket 请求不在 fetch/XHR 拦截范围内
- **二进制响应体**：图片/PDF 等二进制内容不读取，只记录状态码
