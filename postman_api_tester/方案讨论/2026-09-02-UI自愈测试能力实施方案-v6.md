## 一、V6-1【P0】钩子落点缺 job_id——自愈留痕三处依赖全部断链

- **走查证据**：
  - `execute()` 的 `job_id` 是**局部形参**（`ui_headless_engine.py:195`），全函数无处存 `self._job_id`——v3 §三契约表、v4 S1.3/S1.4、v5 V5-3 属性清单**均未安排该属性**。
  - 而钩子一旦采纳需做三件依赖 job_id 的事：① `_take_screenshot(page, job_id, i, "_healed")`（def :2268，形参第一位即 job_id）；② `_log_request(job_id, step_index, request_data)` 事件留痕（模块函数 :47）；③ `self_healing.healed/rejected` 日志事件按 v3 约定携带 job_id。`_find_element`（:1297）签名与 `self` 上均无该值可取——实施到 S1.4 必撞墙，属"编码期才发现"的 P0。
- **修正（覆盖 v3 §三 `__init__` 属性数与 v5 §V5-3 代码块）**：
  ```python
  # __init__ 末尾（:188 self._screenshots_dir 赋值段后）新增 9 属性（v3 "+5"、v5 增量由本条统一钉死）：
  self._job_id: str = ""
  self._healing_active: bool = False
  self._current_step_index: int = -1
  self._current_action: str = ""
  self._current_step: Optional[Dict[str, Any]] = None
  self._last_heal: Optional[Dict[str, Any]] = None
  self._heal_attempts: int = 0
  self._healed_steps: int = 0
  self._heal_once: set = set()          # 或 Set[int]

  # execute() 开头（:213 timeout_ms 取值段前）：
  self._job_id = job_id
  self._healing_active = True
  ```
- **影响风险**：`_healing_active` 默认 False + 仅 `execute()` 置 True，登录链路（V6-3）天然关断；`_job_id` 默认 `""` 使登录链路若有代码路过取值为空串而非 AttributeError。引擎三个构造点均为一次性实例（worker、`ui_execution_routes.py:135`、`ui_login_routes.py:121`），无跨任务复用串值风险，置位无需 finally 复位。
- **规避**：grep 断言新增 **⑫：`_find_element` 内新增 heal 块禁止出现任何 `raise`**（原 :1322-1323 的 `raise` 保持唯一出口；heal 失败绝不允许替换原始异常信息，见 V6-2）；单测 F-1 系列补一例：钩子内 mock `try_heal` 抛 RuntimeError → `_find_element` 仍抛**原** `TimeoutError`（`except Exception` 包裹断言）。

## 二、V6-2【P1】钩子体异常保护未钉死——probe_error 事件 + 原异常照抛

- **走查证据**：v3 §四-M6 仅给出钩子伪码主干，未定义**自愈链自身崩溃**（ui_healing 内 AttributeError、evaluate 超时等）时的行为。钩子插在 `_find_element` 最后候选的 except 分支（:1320-1323 `if is_last: raise` 之前）——若 heal 代码不加保护，自愈的基础设施故障会把原本的"元素未找到"替换成 heal 的内部异常，污染报告 error 字段，违背"N-4 heal 只做加法、失败语义不变"的设计承诺。
- **定稿（覆盖 v3 M6 钩子伪码）**：
  ```python
  # :1320 except 分支内、is_last 时、raise 之前插入：
  if is_last:
      healed_locator = None
      try:
          healed_locator = self._try_self_heal(page)   # 门控+分型+四级全在方法内；
                                                        # 采纳时内部置 self._last_heal（v5 单槽约定不变）
      except Exception as heal_exc:
          self._emit_heal_event("self_healing.probe_error", {"error": str(heal_exc)})
          healed_locator = None                        # 不发 rejected（非策略性拒绝），不吞不改栈
      if healed_locator is not None:
          return healed_locator
      raise                                            # 唯一出口：原样重抛 last_error
  ```
  要点：① heal 链**整体**一个 try/except，except 只发 `probe_error` 事件；② 返回值用**函数局部变量** `healed_locator` 判定，不新增实例属性——`_last_heal` 单槽仍按 v5 约定由 `_try_self_heal` 内部置位、主循环 :763-764 回写；③ `self_healing.probe_error` 登记进 v3 §七日志事件字典（**由 5 事件增至 6 事件**）。
- **规避**：事件字典回归核对纳入 G-2 门禁；F-4 单测断言 probe_error 时 step_result.error 仍为原始 playwright 超时文案。

## 三、V6-3【P2】登录路径实证——N-6 充分性闭环（零改动，钉桩）

- **走查证据**：`execute_login_config`（:903-939）拥有**独立主循环**（:937-943 直接调 `self._execute_step`），**不重入 `execute()`**——`_healing_active` 在登录全程保持 `__init__` 默认 False，即使登录步骤内部 `_execute_step → _find_element` 路过钩子也被门控短路。两处引擎构造点复核：`ui_execution_routes.py:135-136`（`_refresh_auth_from_login_config` in-process）、`ui_login_routes.py:118-122`，均调 `execute_login_config` 且实例即用即弃。
- **结论**：v2 N-6 / v3 对应条款成立且**无需任何额外代码**（不需要在登录路径显式置 False）。记录于此防后续轮次重复怀疑。

## 四、V6-4【P2】`_execute_step_monitored` 重试与钩子交互钉桩

- **走查证据**：monitored 重试结构实证 :1112-1146（while 循环、每轮 `attempt_timeout=min(2000, remaining)`、passed 即返）——同一步骤内 `_find_element` 可被**多次重入**，每次都走到 :1322 最终 raise。
- **定稿（覆盖 v5 §五门控链注释粒度）**：
  - `_heal_once` 于**进入策略链前**（`_heal_attempts += 1` 同刻）加入当前 step index——同步骤第 2~N 次 raise 命"去重短路"（v5 §五链第 4 判），**每步至多消耗 1 次熔断配额**，与 F-15"10 步 ≤5 次 classify"一致。
  - 重试轮次间的等待（2s 循环）发生在 monitored 层，钩子不感知；采纳 heal 后 `_find_element` return locator，monitored 本轮即 passed，不再重入。
  - 跨步骤 `_heal_once` 只增不清（单用例单引擎，worker 进程即用即弃，无泄漏面）。
