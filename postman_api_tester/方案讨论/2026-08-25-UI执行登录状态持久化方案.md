## 1. 背景与问题

### 1.1 现状

当前 UI 自动化测试有两种执行模式：

| 模式 | 实现 | 执行位置 | 登录状态 |
|------|------|----------|----------|
| **浏览器回放** (`browser_replay`) | iframe + JS 回放引擎 | 前端 iframe 内，代理服务转发 | 代理 Cookie jar 管理（`_proxy_session_store`） |
| **无头执行** (`headless`) | Playwright 独立 Chromium | 后端子进程 | **无注入机制，每次新建空浏览器** |

### 1.2 痛点

1. **无头执行无法复用登录状态**：每次执行都是"裸浏览器"，必须从头登录
2. **录制脚本必须包含登录步骤**：增加脚本复杂度，登录步骤与业务步骤耦合
3. **多用例重复登录**：10 个用例需要执行 10 次登录，浪费时间且增加失败风险
4. **浏览器回放依赖实时登录**：虽然回放模式可以复用登录态，但服务重启后丢失，需要重新登录

### 1.3 目标

1. **Phase 1 目标**：无头执行支持加载预保存的 Cookie，跳过登录步骤
2. **Phase 1.5 目标**：录制时保存 Cookie → 多用例复用
3. **Phase 2 目标**：前置登录步骤方案，实现登录与业务逻辑完全解耦
4. **约束**：**对现有功能零影响**，所有改动均为新增可选功能

## 3. 方案 A：storage_state 持久化（Phase 1）

### 3.1 原理

Playwright 原生支持 `storage_state` 功能：

```python
# 保存浏览器状态（Cookie + localStorage）
context.storage_state(path="state.json")

# 加载浏览器状态
context = browser.new_context(storage_state="state.json")
```

保存的 JSON 格式：
```json
{
  "cookies": [
    {"name": "session_id", "value": "abc123", "domain": ".example.com", "path": "/", ...}
  ],
  "origins": [
    {"origin": "http://example.com", "localStorage": [{"name": "token", "value": "xxx"}]}
  ]
}
```

**Phase 1 限制**：
- 仅使用 `cookies` 字段，`origins` 为空数组 `[]`
- Cookie 来源：代理 Cookie jar 导出 或 用户手动构造
- localStorage 支持留到 Phase 2（需要浏览器端 JS 注入提取）

### 3.2 架构设计

**Phase 1 聚焦：仅 Cookie 持久化**

```
┌──────────────────────────────────────────────────────────┐
│                    认证档案存储                            │
│               ui_testing_cases/auth_profiles/            │
│                                                          │
│  auth_{profile_id}.json                                  │
│  ├── name: "生产环境登录"                                 │
│  ├── base_url: "http://example.com"                      │
│  ├── cookies: [{name, value, domain, path, ...}, ...]    │
│  ├── created_at: "2026-08-25T20:00:00"                   │
│  ├── updated_at: "2026-08-25T20:30:00"                   │
│  └── expires_at: "2026-08-26T20:30:00" (可选TTL)        │
└──────────────────┬───────────────────────────────────────┘
                   │
    ┌──────────────┼──────────────────┐
    ▼              ▼                  ▼
┌────────┐  ┌────────────┐   ┌──────────────┐
│ 录制时  │  │ 手动上传    │   │ 前置登录步骤  │
│ 导出Cookie│ │ Cookie JSON│   │ (Phase 2)   │
└────────┘  └────────────┘   └──────────────┘
    │              │                  │
    └──────────────┼──────────────────┘
                   ▼
┌──────────────────────────────────────────────────────────┐
│              UiHeadlessEngine.execute()                  │
│                                                          │
│  # 从 auth_profile 构造 storage_state                     │
│  storage_state = {                                       │

│  )                                                       │
│  → 浏览器启动即带有登录状态                               │
│  → 直接执行业务步骤，无需登录                              │
└──────────────────────────────────────────────────────────┘
```

**Phase 1 边界说明**：
- ✅ 仅支持 Cookie 持久化（来自代理 Cookie jar 或手动上传）
- ❌ 不包含 localStorage（需要浏览器端 JS 提取，复杂度较高，留到 Phase 2）
- ❌ 不包含浏览器回放模式预加载（回放模式现有机制已可用，Phase 1 聚焦无头执行）

#### 3.5.3 修改 `services/ui_headless_engine.py`

**改动点**：`execute()` 方法支持 `auth_state_path` 参数，带防御性校验。

> **v4 修正（兜底）**：Playwright `new_context(storage_state=...)` 在文件格式错误时会抛异常导致整个执行失败。需增加 JSON 格式校验，失败时降级为无登录状态执行。

```python
def execute(
    self,
    steps: List[Dict[str, Any]],
    base_url: str,
    options: Dict[str, Any],
    job_id: str,
    cancel_flag: Optional[Any] = None,
    on_step_complete: Optional[Any] = None,
    on_browser_ready: Optional[Any] = None,
    auth_state_path: Optional[str] = None,  # ← 新增参数
) -> Dict[str, Any]:
    ...
    # 改动位置：创建 context 时加载登录状态（带防御性校验）
    context_kwargs: Dict[str, Any] = {
        "viewport": {"width": viewport_w, "height": viewport_h},
    }
    storage_state = _validate_auth_state_file(auth_state_path, job_id)
    if storage_state is not None:
        context_kwargs["storage_state"] = storage_state

    context = browser.new_context(**context_kwargs)
    ...


def _validate_auth_state_file(
    auth_state_path: Optional[str], job_id: str
) -> Optional[Dict[str, Any]]:
    """校验 auth_state 文件存在性和 JSON 格式。

    返回 storage_state 字典（可直接传给 Playwright），
    校验失败返回 None（降级为无登录状态执行）。
    """
    if not auth_state_path:
        return None
    path = Path(auth_state_path)
    if not path.exists():
        logger.warning(
            "headless_auth_state_file_missing",
            extra={
                "event": "headless.auth_state_file_missing",
                "auth_state_path": auth_state_path,
                "job_id": job_id,
            },
        )
        return None
    try:
        data = json.loads(path.read_text(encoding="utf-8"))
        if not isinstance(data, dict):
            raise ValueError("storage_state must be a JSON object")
        if "cookies" not in data:
            raise ValueError("storage_state missing 'cookies' field")
        cookie_count = len(data.get("cookies", []))
        logger.info(
            "headless_auth_state_validated",
            extra={
                "event": "headless.auth_state_validated",
                "auth_state_path": auth_state_path,
                "job_id": job_id,
                "cookie_count": cookie_count,
            },
        )
        # Playwright 接受 dict 或 file path，此处返回 dict 避免重复读文件
        return data
    except (json.JSONDecodeError, OSError, ValueError) as e:
        logger.error(
            "headless_auth_state_invalid",
            extra={
                "event": "headless.auth_state_invalid",
                "auth_state_path": auth_state_path,
                "job_id": job_id,
                "error": str(e),
            },
        )
        return None  # 降级：不加载登录状态
```

**关键**：
- 只新增一个可选参数 `auth_state_path`，不传时行为与现有完全一致
- 文件不存在 / JSON 格式错误 / 缺少 cookies 字段 → 日志告警 + 降级为无登录状态执行（不抛异常）
- Playwright `new_context()` 接受 `storage_state` 为 dict 或 file path，此处传 dict 避免重复读文件

**改动点**：`start_headless()` 方法接收并传递 `auth_state_path`，并在 `finally` 块中清理临时文件。

> **v4 修正（兜底）**：现有 `finally` 块仅在 `run()` 内部函数中。若线程启动前就失败（如 `_worker_input_json` 异常），`finally` 不会执行，auth_state 临时文件会泄漏。需在外层也加兜底清理。

```python
def start_headless(
    self,
    job_id: str,
    case_data: Dict[str, Any],
    options: Dict[str, Any],
    on_complete: Optional[Callable] = None,
    auth_state_path: Optional[str] = None,  # ← 新增
) -> None:
    ...
    input_file = _worker_input_json(
        job_id, case_data, options, screenshots_dir,
        auth_state_path=auth_state_path,  # ← 新增
    )

    cancel_event = threading.Event()
    process: Optional[subprocess.Popen[Any]] = None

    with _lock:
        _active_jobs[job_id] = {
            "cancel_event": cancel_event,
            "process": None,
        }

    self._store.update_status(job_id, "starting")

    def run() -> None:
        nonlocal process
        try:
            # ... 现有逻辑不变 ...
        finally:
            with _lock:
                _active_jobs.pop(job_id, None)
            try:
                os.unlink(input_file)
            except OSError:
                pass
            # 清理 auth_state 临时文件 ← 新增
            _cleanup_auth_state(auth_state_path)

    t = threading.Thread(target=run, name=f"ui-exec-{job_id}", daemon=True)
    with _lock:
        if job_id in _active_jobs:
            _active_jobs[job_id]["thread"] = t
    try:
        t.start()
    except RuntimeError:
        # 兜底：线程启动失败（极端情况），手动清理临时文件
        logger.error(
            "ui_execution_thread_start_failed",
            extra={
                "event": "ui.execution.thread_start_failed",
                "job_id": job_id,
            },
        )
        _cleanup_auth_state(auth_state_path)
        try:
            os.unlink(input_file)
        except OSError:
            pass
        self._store.finalize_job(job_id, "failed", {
            "steps_total": 0, "steps_passed": 0,

def _convert_cookie_jar_to_playwright(
    jar: "requests.cookies.RequestsCookieJar",
) -> List[Dict[str, Any]]:
    """将 requests CookieJar 转换为 Playwright storage_state cookies 格式。"""
    cookies = []
    for c in jar:
        cookie: Dict[str, Any] = {
            "name": c.name,
            "value": c.value,
            "domain": c.domain or "",
            "path": c.path or "/",
            # 与 ui_proxy_service.get_set_cookie_headers() 一致的检测方式
            "httpOnly": bool(c.has_nonstandard_attr("HttpOnly")),
            "secure": bool(c.secure),
            # sameSite: 优先读取 cookie 属性，无则默认 Lax
            "sameSite": _get_same_site(c),
        }
        if c.expires is not None:
            cookie["expires"] = c.expires
        else:
            cookie["expires"] = -1  # Session cookie
        cookies.append(cookie)
    return cookies


def _get_same_site(cookie: "requests.cookies.RequestCookie") -> str:
    """从 Cookie 对象提取 SameSite 属性，默认 Lax。"""
    # requests 库将 SameSite 存为 _rest dict 中的非标准属性
    ss = cookie.get_nonstandard_attr("SameSite")
    if ss:
        # 规范化：Strict / Lax / None
        ss_lower = ss.lower()
        if ss_lower == "strict":
            return "Strict"
        elif ss_lower == "none":
            return "None"
    return "Lax"
```

**关键修正**：
- 录制会话**没有** `proxy_session_id` 字段，必须通过 `base_url` 反查
- **必须**先将 base_url 提取为 origin（`scheme://netloc`），再调用 `find_session_by_base_url`，否则含路径的 URL 无法匹配
- `find_session_by_base_url` 使用**精确匹配**，这是已知限制（见风险 10.1 应对）
- 仅导出 Cookie，不包含 localStorage（Phase 1 边界）
- Cookie 格式需转换为 Playwright storage_state 格式
- `_convert_cookie_jar_to_playwright` 与现有 `ui_proxy_service.get_set_cookie_headers()` 的 HttpOnly 检测方式一致（line 344）
- 返回字段保持向后兼容（原有字段 + 新增 `cookies_for_export`）

## 4. 方案 C：前置登录步骤（Phase 2）

### 4.1 原理

将登录操作抽象为独立的"登录配置"，执行前自动运行登录步骤，保存状态后供业务用例使用。

```
┌──────────────────────────────────────────────────────────┐
│                    登录配置                               │
│                                                          │
│  login_config_id: "login_001"                            │
│  name: "管理员登录"                                      │
│  base_url: "http://example.com"                          │
│  login_steps: [                                          │
│    {"action": "navigate", "value": "/login"},            │
│    {"action": "type", "selector": "#username", "value": "admin"}, │
│    {"action": "type", "selector": "#password", "value": "xxx"}, │
│    {"action": "click", "selector": "#login-btn"},        │
│    {"action": "wait_for", "value": "/dashboard"},        │
│  ]                                                       │
│  success_condition:                                      │
│    url_pattern: "/dashboard"                             │
│    或 cookie_exists: "JSESSIONID"                        │
└──────────────────┬───────────────────────────────────────┘
                   │
                   ▼
┌──────────────────────────────────────────────────────────┐
│              前置登录执行流程                              │
│                                                          │
│  1. 启动 Playwright 浏览器（临时 context）               │
│  2. 执行 login_steps                                     │
│  3. 验证 success_condition                               │
│  4. 成功 → context.storage_state(path=临时文件)          │
│  5. 关闭临时浏览器                                       │
│  6. 业务用例执行时加载该 storage_state                   │
└──────────────────────────────────────────────────────────┘
```

### 4.2 数据模型

#### 登录配置 (LoginConfig)

```json
{
  "id": "login_001",
  "name": "管理员登录",
  "description": "管理系统管理员账号登录",
  "base_url": "http://192.168.1.100:8080",
  "login_steps": [
    {"action": "navigate", "value": "/login", "selector": {}, "tag": "", "tag_text": ""},
    {"action": "type", "selector": {"primary": "#username", "type": "css"}, "value": "admin", "tag": "input", "tag_text": ""},
    {"action": "type", "selector": {"primary": "#password", "type": "css"}, "value": "password123", "tag": "input", "tag_text": ""},
    {"action": "click", "selector": {"primary": "#login-btn", "type": "css"}, "value": "", "tag": "button", "tag_text": "登录"},
    {"action": "wait_for", "value": "/dashboard", "selector": {}, "tag": "", "tag_text": ""}
  ],
  "success_condition": {
    "type": "url_pattern",
    "value": "/dashboard"
  },
  "created_at": "2026-08-25T20:00:00",
  "updated_at": "2026-08-25T20:30:00"
}
```

**success_condition 类型**：
- `url_pattern`: URL 包含指定路径
- `cookie_exists`: 存在指定名称的 Cookie
- `element_exists`: 页面存在指定选择器的元素
- `no_redirect`: 未重定向到 `/login` 或 `/error`

### 4.3 执行流程

```
用户点击"执行"
  → api_ui_testing_execute(case_id)
    → 检查用例是否关联了 login_config_id
    → 如果有：
      1. 启动临时 Playwright 浏览器
      2. 执行 login_steps
      3. 验证 success_condition
      4. 成功 → 保存 storage_state 到临时文件
      5. 关闭临时浏览器
    → 启动业务用例浏览器
      → 加载 storage_state
      → 执行业务步骤
```

### 4.4 录制登录步骤

#### 专用登录录制模式

```
1. 用户在用例编辑器中选择"录制登录步骤"
2. 系统创建临时录制会话
3. 用户在 iframe 中执行登录操作
4. 系统自动捕获步骤并标记为"登录步骤"
5. 录制完成后，弹出"验证登录成功"对话框：
   - 当前 URL 是否已跳转到目标页面？  [✓]
   - 是否出现登录成功的标志（如用户名显示）？ [✓]
6. 系统保存为 login_config
```

#### 登录步骤的特殊标记

登录步骤在录制时自动添加 `is_login_step` 元数据标记（现有功能已支持），便于：
- 回放时跳过或特殊处理
- 日志中标记登录阶段
- 统计登录耗时

### 4.5 与方案 A 的关系

```
方案 A (storage_state 持久化)
  └─ 提供基础能力：保存/加载浏览器状态
  └─ 状态来源：手动录制 / 手动上传

方案 C (前置登录步骤)
  └─ 建立在方案 A 之上
  └─ 状态来源：自动执行登录步骤
  └─ 额外能力：登录步骤的录制、编辑、验证

两者可独立使用，也可组合：
  - 只用方案 A：手动保存状态，多用例复用
  - 只用方案 C：每次执行前自动登录
  - A + C：自动登录后保存状态，后续用例直接加载（减少登录频率）
```

## 5. 对现有功能的影响评估

### 5.1 零影响保证

| 组件 | 改动类型 | 影响 |
|------|----------|------|
| 录制功能 | 停止时返回 `cookies_for_export` | 不影响现有录制流程，仅新增返回字段（前端 fire-and-forget） |
| 浏览器回放 | 无改动 | 完全不受影响（继续依赖代理 Cookie 机制） |
| 无头执行（无 auth_profile_id） | 无改动 | 行为与现有完全一致 |
| **执行路由 `clear_login` 逻辑** | **仅浏览器回放模式清除代理 Cookie** | ✅ **v5 修正**：无头模式不再清除代理 Cookie，避免影响后续浏览器回放 |
| 用例存储 `create_case()` | 字段构造新增 `auth_profile_id` | 向后兼容：`case.get("auth_profile_id") or None` 缺省返回 `None`，旧调用方不受影响 |
| 用例存储 `update_case()` | 白名单新增 `"auth_profile_id"` + 空字符串规范化 | 向后兼容：不传时行为不变，传空字符串时规范化为 `None` |
| 用例存储 `list_cases()` | 摘要新增 `auth_profile_id` 字段 | 向后兼容：旧用例无此字段返回 `None`，前端按 falsy 处理即可 |
| 前端编辑器 `ui_testing_editor.html` | 新增认证档案下拉框 + 保存/回显逻辑 | 纯新增 UI 元素，不修改现有表单字段 |
| 前端编辑器 `executeCase()` | 新增 `auth_profile_id` 传递 | 可选覆盖，不传时使用用例中保存的值 |
| 前端列表 `ui_testing_index.html` | 可选：显示关联的认证档案名称 | Phase 1.5 可选，不影响现有列表功能 |
| 设置存储 | 无改动 | 不受影响 |
| 代理服务 | 无改动 | 不受影响（仅读取 Cookie jar） |

### 5.2 向后兼容

- 用例 JSON 文件中 `auth_profile_id` 为可选字段，缺失时行为不变
- `update_case()` 白名单扩展：不传 `auth_profile_id` 时不会修改已有值
- 认证档案存储使用独立目录 `ui_testing_cases/auth_profiles/`，不影响现有 `case_*.json`
- API 路由使用 `/api/ui-testing/auth-profiles` 前缀，不与现有路由冲突
- `storage_state` 功能为 Playwright 原生支持，无需额外依赖
- 前端录制停止接口返回值变更：新增 `cookies_for_export` 字段，现有前端 `ui_testing_recorder.html` 是 fire-and-forget 不使用返回值，Chrome 扩展走另一条链路

### 5.3 风险点与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| Cookie 过期导致执行失败 | 高 | 中 | 添加 `expires_at` 字段 + 过期检查 + 执行前校验 + 日志告警 |
| Cookie 域名不匹配 | 低 | 中 | 保存时校验 base_url 与 Cookie domain 一致性 |
| 认证档案泄露（含敏感 Token） | 低 | 高 | 文件权限限制 + Cookie value 日志脱敏 + 独立目录 |
| 临时文件残留 | 低 | 低 | `finally` 块中清理 + 定期清理 temp/ 目录 |
| 仅 Cookie 不含 localStorage 导致部分应用无效 | 中 | 中 | 文档明确说明 Phase 1 限制，引导用户手动补充或使用 Phase 2 |
| `find_session_by_base_url` 精确匹配失败 | 中 | 低 | 录制时提取 origin（scheme+host+port）；匹配失败时降级为空 Cookie 导出 |
| 前端编辑器保存时覆盖已有 `auth_profile_id` | 低 | 低 | 下拉框回显当前值；不修改时保持原值不变 |

| M5 | 并发执行同一认证档案的临时文件冲突 | 低 | 低 | 文件名 `auth_state_{job_id}.json` | ✅ 安全：`job_id` 全局唯一，不会冲突 |
| M6 | CookieJar 为空时导出空数组 | 中 | 低 | 录制时未产生任何 Cookie | ✅ 安全：空数组 → storage_state 无 Cookie → 等效无登录状态 |

## 11. 兜底设计

> v4 新增：每个失败场景的降级策略，确保方案不会导致系统崩溃或数据丢失。

### 11.1 兜底原则

1. **认证档案是可选增强**：所有路径都必须能在无档案时正常工作
2. **降级不中断**：Cookie 加载失败 → 降级为无登录执行，不中断任务
3. **临时文件必清理**：所有创建临时文件的路径必须有对应的清理逻辑
4. **日志可追踪**：每个降级场景都有独立的结构化日志事件

### 11.2 失败场景与降级策略

#### 场景 1：认证档案不存在

```
触发：用例引用了 auth_profile_id，但档案已被删除
检测：_auth_profile_store.get_profile() 返回 None
降级：auth_state_path = None → engine.execute() 不加载 storage_state
日志：ui.execution.auth_profile_not_found (warning)
用户感知：无头执行正常启动，但无登录状态（可能因未登录而失败）
```

#### 场景 2：认证档案已过期

```
触发：Cookie 超过 expires_at 时间
检测：_auth_profile_store.is_expired(profile) 返回 True
降级：auth_state_path = None → 不加载 storage_state
日志：ui.execution.auth_profile_expired (warning)
用户感知：同场景 1
```

#### 场景 3：auth_state 临时文件写入失败

```
触发：temp/ 目录权限不足、磁盘满
检测：_write_auth_state_temp() 抛出 OSError
降级：try/except 捕获 → auth_state_path = None
日志：ui.execution.auth_temp_write_failed (error)
用户感知：同场景 1
```

#### 场景 4：auth_state 临时文件被提前删除或损坏

```
触发：外部清理 temp/、磁盘故障
检测：_validate_auth_state_file() 文件不存在或 JSON 解析失败
降级：返回 None → context_kwargs 不含 storage_state
日志：headless.auth_state_file_missing / headless.auth_state_invalid (error)
用户感知：同场景 1
```

#### 场景 5：auth_state 临时文件泄漏

```
触发：线程启动前异常（极端情况）
检测：finally 块未执行
兜底：start_headless() 外层 try/except → _cleanup_auth_state()
日志：ui.execution.thread_start_failed (error)
用户感知：无（文件被清理）
```

#### 场景 6：录制时代理会话已过期

```
触发：录制超过 1 小时，代理会话被 TTL 清理
检测：find_session_by_base_url(origin) 返回 None
降级：cookies_for_export = []
日志：ui.recording.proxy_session_not_found (warning)
用户感知：前端对话框显示"未找到登录状态，请重新录制"
```

#### 场景 7：CookieJar 为空

```
触发：录制时未产生任何 Cookie（纯静态页面）
检测：len(cookie_jar) == 0
降级：cookies_for_export = []
日志：ui.recording.no_cookies_to_export (info)
用户感知：前端对话框显示"当前无 Cookie 可保存"
```

#### 场景 8：前端传空字符串 auth_profile_id

```
触发：下拉框选择"不使用"，值为 ""
检测：create_case/update_case 中 `not value` 判断
降级：规范化为 None 存储
日志：无（静默处理）
用户感知：无
```

### 11.3 兜底覆盖矩阵

| 失败点 | 检测层 | 降级策略 | 日志事件 | 是否中断执行 |
|--------|--------|----------|----------|-------------|
| 档案不存在 | 路由层 | auth_state=None | auth_profile_not_found | ❌ 不中断 |
| 档案过期 | 路由层 | auth_state=None | auth_profile_expired | ❌ 不中断 |
| 临时文件写入失败 | 路由层 | auth_state=None | auth_temp_write_failed | ❌ 不中断 |
| 临时文件丢失/损坏 | 引擎层 | auth_state=None | auth_state_file_missing | ❌ 不中断 |
| 临时文件泄漏 | 管理器层 | 手动清理 | thread_start_failed | ❌ 不中断 |
| 代理会话过期 | 路由层 | cookies=[] | proxy_session_not_found | ❌ 不中断 |
| CookieJar 为空 | 路由层 | cookies=[] | no_cookies_to_export | ❌ 不中断 |
| 空字符串 auth_profile_id | 存储层 | 规范化为 None | 无 | ❌ 不中断 |

### 11.4 兜底设计总结

**核心结论**：方案的所有改动路径都有对应的降级策略，**任何单点失败都不会导致系统崩溃或数据丢失**。最差情况是退化为现有行为（无登录状态的裸浏览器执行），与未引入此方案时完全一致。
